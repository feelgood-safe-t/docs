## 2. 아이디어 기획 핵심내용(요약) *

> *(양식 요구: 전체 기획의 핵심 내용을 요약하여 **개조식**으로 간략히)*

- **한 줄 정의** — 자연어로 시장 환경을 만들고, AI 에이전트가 시장 참여자로 반응하는 **가명화 모의시장**에서, 수익률이 아닌 **'의사결정 과정'으로 투자 역량을 진단·인증**하는 AI 금융교육 플랫폼

- **문제** — 2026년 8월 19일부터 단일종목 레버리지 상품 신규 개인투자자에게 **모의거래 이수가 의무화**되었으나, 그 요건은 *'5거래일 × 1시간'* 이라는 **시간 충족 조건**일 뿐 **이해도를 측정하지 않는다**. 이수증은 발급되지만 학습은 검증되지 않는다.

- **해법 3단** —
  1. **시나리오 생성** : 사용자의 투자 성향·취약점을 진단하고, LLM이 *"고금리 지속 + 외국인 순매도 + 실적 쇼크"* 같은 **자연어 시장 가정**을 시뮬레이션 파라미터로 변환해 **개인 맞춤 시장**을 생성
  2. **살아있는 시장** : 모멘텀추종·역추세·기관·군집투자 등 **AI 에이전트가 시장 참여자이자 환경 그 자체**로 작동. 사용자의 주문이 호가에 영향을 주고, 급락장에서는 **"팔고 싶어도 팔리지 않는 경험"**까지 재현
  3. **과정 기반 진단·인증** : 수익률이 아니라 **손절 준수율·포지션 사이징·레버리지 노출 시간·뉴스 반응 편향·물타기 지수** 등 행동 지표를 채점해 LLM이 디브리핑 리포트를 생성하고, **역량 기반 이수증**을 발급

- **차별성 한 줄** — 기존 모의투자가 *"실전 주문 화면에 익숙해지는 곳"*이라면, SAFE-T는 *"실전에서 잃을 돈을 미리 잃고 그 이유를 진단받는 곳"*

- **핵심 설계 원칙** — 표시되는 **종목명·가격은 100% 가명화·합성**. 실제 종목을 쓰지 않기에 학습자가 정답을 검색할 수 없고, **매 세션 새로운 시장**이 생성된다

- **활용처** — ① 고위험 상품 신규 진입 개인투자자(B2C) ② 증권사·거래소의 투자자보호 이수 프로그램(B2B) ③ 학교·기관 금융교육(B2G)

## 3. 문제 정의 및 제안 배경 *

> *(양식 요구: 구체적 문제점 + **특정 금융 고객**과 **채널**을 선택한 배경·이유)*

### 3.1 배경 — 2026년, 규제가 상품을 따라잡는 데 84일이 걸렸다

| 시점 | 사건 |
|---|---|
| 2026-05-27 | 삼성전자·SK하이닉스 기초 **단일종목 레버리지·인버스(2×) ETF 상장** |
| ~ 2026-06-19 | 개인투자자 누적 순매수 **약 8.2조 원** |
| 2026-06-23 | 시장 급락 → 해당 ETF 14종 **하루 평균 -25.05%** |
| 2026-08 중순 | 일간 거래대금 10조 원대 → **1조 원대 이하 급감** |
| **2026-08-19** | **신규 개인투자자 모의거래 이수 의무화 시행** |

동시에 국내 금융소비자의 **디지털 금융이해력은 59.3점**으로 OECD 목표(70점)를 밑돌고, 조사대상의 **70% 이상이 저이해력 집단**에 속한다. 같은 조사는 **금융서비스 이용 경험이 이해력을 2.2~3.5점 끌어올린다**고 보고한다. → **경험이 이해를 만든다. 그러나 그 경험은 실제 돈으로 사서는 안 된다.**

### 3.2 문제 정의 — 3층 구조

**P1. 상품 위험도와 투자자 이해도의 격차**
레버리지·인버스는 **일간 수익률 배수 추종**으로 인해 **변동성 잠식(volatility decay)**이 발생하며, 횡보장에서도 원금이 녹는다. 이 개념은 텍스트 교육으로는 거의 전달되지 않는다. *체감해야만 이해되는 위험*이다.

**P2. 이수 제도가 "시간"만 측정하고 "이해"를 측정하지 않는다**

| 현행 이수 요건 | 측정하는 것 | 측정하지 않는 것 |
|---|---|---|
| 총 5거래일 이상 접속·거래 | 접속 일수 | 손실 상황에서의 의사결정 |
| 매 거래일 1시간 이상 | 체류 시간 | 리스크 개념의 이해 여부 |
| HTS 설치 후 정규장/Replay장 이용 | 주문 실행 능력 | 왜 그 주문을 냈는지 |

→ **창을 띄워놓기만 해도 이수증이 발급되는 구조.** 제도의 취지("리스크를 명확히 인지하고 투자")와 실행 사이에 공백이 있다.

**P3. 기존 모의투자 서비스는 학습을 만들지 못한다**

| # | 한계 | 결과 |
|---|---|---|
| C1 | 실제 종목·실제 과거 데이터(Replay) | 종목명을 아는 순간 **정답을 검색**할 수 있다 |
| C2 | 수익률 랭킹 중심 | **몰빵한 사람이 1등** — 잘못된 행동을 강화 |
| C3 | 전원 동일 시나리오 | 개인의 취약점(손절 불능, 과잉확신)을 겨냥하지 못함 |
| C4 | 이수 후 피드백 없음 | 무엇을 왜 잘못했는지 모른 채 종료 |
| C5 | 시장이 반응하지 않음 | **급락장의 유동성 증발**을 경험할 수 없음 |

### 3.3 타깃 금융 고객 (선택 배경) 🔴 *팀 확정 필요*

**1차 타깃 — 고위험 상품에 신규 진입하려는 20~30대 개인 일반투자자**
- **선택 이유 ①** 2026-08-19 이수 의무화의 **법적 대상자**와 정확히 일치 → 제도가 이미 수요를 만들어 두었다
- **선택 이유 ②** 대회 세부 주제 예시 중 *"청년층 자산 형성 … AI 기반 포용적 금융서비스"*에 직접 부합
- **선택 이유 ③** 투자 경험이 짧아 **손실 경험의 학습 비용이 가장 비싼** 집단

**2차 타깃(B2B) — 증권사·거래소의 투자자보호/교육 담당 부서**
- 이수 프로그램을 운영해야 하지만 **역량 측정 수단이 없는** 주체

### 3.4 채널 선택 (선택 배경)

**모바일 웹(Mobile-first Web) 우선 — 데스크톱 반응형 지원**

| 근거 | 설명 |
|---|---|
| **제도-현실 불일치 해소** | 현행 KRX 모의거래는 **HTS 전용이며 MTS(모바일) 불가**. 그러나 20~30대 개인투자자의 실제 거래 채널은 압도적으로 모바일이다. **"모바일에서 배우고 모바일에서 거래한다"**는 채널 일치가 학습 전이(transfer)를 만든다 |
| **접근 마찰 최소화** | 설치·인증서 없이 URL 하나로 진입 → 포용적 금융의 전제 |
| **대회 요건 정합** | 심사는 **배포 URL로 진행**된다. 웹이 곧 제출물 |

## 4. 서비스 컨셉 및 차별성 *

### 4.1 서비스 컨셉 — "AI가 만든 시장에서, AI가 채점한다"

```
 ┌───────────────┐   ┌────────────────┐   ┌──────────────┐   ┌───────────────┐
 │ ① 성향 진단    │→ │ ② 시나리오 생성  │→ │ ③ 훈련 세션   │→ │ ④ 디브리핑     │
 │ 투자 성향·경험 │   │ 자연어 시장 가정 │   │ AI 에이전트가 │   │ 과정 채점 +   │
 │ ·취약점 프로파일│   │ → 시뮬 파라미터  │   │ 참여자이자 환경│   │ 이수증 발급    │
 └───────────────┘   └────────────────┘   └──────────────┘   └───────────────┘
                              ▲                                        │
                              └───────── 취약점 재배정 (다음 세션) ──────┘
```

**계층 1 — 자연어 시나리오 오케스트레이션**
사용자 또는 교육 운영자가 *"금리 인상 지속, 외국인 대량 순매도, 반도체 업황 둔화"* 를 자연어로 입력하면, LLM이 이를 **드리프트·변동성·점프 강도·이벤트 스케줄·에이전트 성향 분포**로 변환해 시장을 생성한다.

**계층 2 — AI 에이전트 = 시장 참여자이자 환경**
모멘텀추종형 / 역추세형 / 기관형 / 군집(패닉)형 페르소나 에이전트가 뉴스와 호가에 반응하며 **가격을 내생적으로 형성**한다. 사용자의 대량 주문은 호가를 밀어 **슬리피지**를 만들고, 패닉 구간에서는 **매도 호가가 사라지는 유동성 증발**이 재현된다.
> 학술적 근거: LLM 멀티에이전트 시장 시뮬레이션(StockAgent, arXiv:2407.18957)이 이미 검증한 방향이며, **우리는 이를 알파 추구 연구 도구가 아니라 '사람을 훈련시키는 교육 제품'으로 전환**한다.

**계층 3 — 과정 기반 진단 및 인증**
결과(수익률)가 아니라 **행동**을 채점한다.

| 지표 | 측정 내용 | 대응 금융 개념 |
|---|---|---|
| 손절 준수율 | 사전 선언한 손절선을 실제로 지켰는가 | 손실 회피 편향 |
| 포지션 사이징 | 1회 베팅이 자산에서 차지한 비중 | 켈리/리스크 예산 |
| 레버리지 노출 시간 | 레버리지 상품 보유 일수 | 변동성 잠식 |
| 물타기 지수 | 하락 중 추가 매수 빈도·규모 | 매몰비용 오류 |
| 뉴스 반응 지연/과잉 | 가상 뉴스 발생 후 주문까지의 시간·규모 | 확증편향·과잉반응 |
| 분산도 | 종목·섹터 집중도 | 분산투자 |

### 4.2 기존 금융 앱 대비 차별성 (5)

| # | 차별성 | 기존 서비스 | SAFE-T |
|---|---|---|---|
| **D1** | **가명화·합성 시장** | 실제 종목·실제 과거 데이터 → 검색으로 정답 확인 가능, Replay는 결과를 이미 앎 | 종목명·가격 전부 합성. **정답이 존재하지 않는다.** 매 세션 새 시장 |
| **D2** | **과정 채점** | 수익률 랭킹 → 몰빵이 1등 | 행동 지표 채점 → **운으로 통과할 수 없다** |
| **D3** | **개인 맞춤 시나리오** | 전원 동일 | 성향 진단 + 과거 행동 로그 → **약점을 겨냥한 시장 배정** |
| **D4** | **반응하는 시장** | 정적 데이터 재생 | AI 에이전트가 사용자 주문에 반응 → **슬리피지·유동성 증발 체감** |
| **D5** | **AI 디브리핑 + 역량 인증** | 피드백 없음, 시간 기반 이수 | LLM 리포트 + **SAFE-T 이수 리포트**(역량 기반) — 제도의 형식성을 보완 |

### 4.3 우리가 하지 않는 것 (스코프 방어)
- 실제 종목에 대한 **투자 자문·추천·수익률 예측을 하지 않는다** → 투자자문업 규제 회피 및 서비스 철학 일관성
- 실제 주문 체결·자금 이동 없음 → 금전 리스크 0
- 수익률 랭킹 보드를 만들지 않는다 → **게임화의 도박화 전이 차단**

## 5. 활용 데이터 및 생성형 AI 모델 적용 방안 *

> *(양식 요구: 데이터 종류·수집·활용 방안 + **생성형 AI가 서비스 내에서 수행하는 역할을 구체적으로**)*

### 5.1 활용 데이터

| 구분 | 데이터 | 출처·수집 방안 | 활용 |
|---|---|---|---|
| **시장 통계** | 변동성, 수익률 분포, 점프 빈도, 섹터 상관계수, 거래량 프로파일 | KRX 정보데이터시스템 등 **공개 시세**에서 통계량만 추정 | 합성 시장의 **파라미터 캘리브레이션 전용**. 실제 시세를 화면에 표시하지 않음 |
| **가명 종목 유니버스** | 가상 기업명·섹터·재무 프로파일·사업 개요 | **LLM 생성** | 시장 구성. 실존 기업과 무관 |
| **시나리오 정의** | 국면(bull/bear/harsh), 이벤트 스케줄, 에이전트 성향 분포 | 자연어 입력 → LLM 구조화 | 시뮬레이션 구동 |
| **사용자 성향 데이터** | 투자 경험, 위험 감내도, 관심 섹터, 목표 (설문 10~12문항) | 서비스 내 온보딩 설문 | 시나리오 배정 |
| **행동 로그** | 주문 시각·수량·가격, 보유 기간, 뉴스 노출 후 반응, 손절 선언 대비 실행 | 서비스 자체 생성 | 과정 채점, 디브리핑 |

**개인정보 처리 방침 (설계 원칙)**
- 실명·주민번호·계좌번호·실제 보유종목 **일절 수집하지 않음**
- 로그인은 익명 세션 또는 이메일 단일 식별자 (MVP는 익명 세션 우선)
- 행동 로그는 **서비스 내부에서 생성된 가상 거래 기록**이므로 금융거래정보에 해당하지 않음
- → **민감정보 미처리. 데이터 유출 시 금융 피해가 발생하지 않는 구조** *(주최기관인 금융보안원의 관점에서 유의미한 설계 선택)*

### 5.2 생성형 AI 모델 적용 방안 — 4개 용처

| # | 역할 | 입력 | 출력 | 왜 LLM이어야 하는가 |
|---|---|---|---|---|
| **A. 시나리오 오케스트레이터** | 자연어 시장 가정 → 시뮬레이션 파라미터 | *"고금리 지속 + 외국인 순매도 + 실적 쇼크"*, 사용자 성향 프로파일 | JSON: 드리프트·변동성·점프 강도·이벤트 타임라인·에이전트 분포 | **비정형 서술을 구조화된 파라미터로 사상**하는 작업. 규칙 기반으로는 조합 폭발 |
| **B. 시장 참여자 에이전트** | 뉴스·호가를 해석해 매매 의사결정 | 가상 뉴스, 현재 호가·포지션, 페르소나 프롬프트 | 주문(방향·수량·가격) + 판단 근거 | **뉴스라는 비정형 정보에 대한 해석 편차**가 시장을 만든다. 이 편차가 LLM의 본질적 강점 |
| **C. 시장 내러티브 엔진** | 가명 종목의 가상 공시·뉴스·커뮤니티 여론 생성 | 시나리오 상태, 가격 궤적, 진행 이벤트 | 뉴스 헤드라인·본문·게시글 | 가격 움직임에 **서사적 개연성**을 부여해 학습자가 "판단"할 재료를 만든다 |
| **D. 디브리핑 애널리스트** | 행동 로그 → 진단 리포트 | 전체 거래 로그, 과정 지표 점수 | 자연어 리포트, 편향 진단, 개선 과제, 다음 시나리오 추천 | 정량 지표를 **개인의 언어로 설명**해야 행동이 바뀐다 |

**모델 운용 방안**
- **온프레미스 우선:** 자체 DGX 서버에 Qwen3 계열 오픈 모델 서빙 — 비용 통제 및 **데이터 외부 반출 없음** 🔴 *정확한 모델 ID 확인 필요 (`Qwen/Qwen3.8-27B`는 오타로 보임 — HuggingFace에서 실존 ID 확인)*
- **역할별 분리:** B(에이전트)는 다수 호출이 필요하므로 **경량 모델 + 배치**, A/D는 품질이 중요하므로 **고성능 모델**
- **결정성 확보:** 시나리오 시드 고정으로 동일 조건 재현 가능 (심사자 검증용)
- 🔴 **가용성 리스크:** 배포 URL은 **9/7 11:00 ~ 9/11 23:59 무중단 접속 필수(불가 시 결격)**. 자체 서버 장애 대비 **상용 API 폴백 경로 또는 사전 생성 캐시**를 반드시 준비할 것

### 5.3 책임 있는 생성 — 가상 뉴스 오남용 방지 *(→ 7번 항목에서 상술)*

## 6. 기대 효과 및 확장 가능성 *

### 6.1 해결하는 문제와 기대 효과

| 대상 | 기대 효과 |
|---|---|
| **개인투자자** | 실제 손실 없이 **변동성 잠식·유동성 증발·손절 실패**를 체감. 자신의 행동 편향을 **데이터로 통보받는 최초의 경험** |
| **증권사·거래소** | 시간 기반 이수제를 **역량 기반으로 보완**할 수 있는 측정 도구 확보. 투자자보호 의무 이행의 실질화 |
| **감독 당국** | 이수자의 **집계 행동 데이터**를 통해 "어떤 개념이 실제로 이해되지 않는가"를 최초로 정량 파악 |
| **학교·기관** | 교사가 자연어로 시장을 만들어 배포하는 **금융교육 교보재** |

### 6.2 정량 목표 🟡 *(설문 결과 확보 후 수치 확정)*
- 세션 전후 **금융 개념 이해도 사전/사후 테스트 점수 향상률**
- 반복 세션 간 **손절 준수율 개선폭**, **최대 포지션 비중 감소폭**
- 이수 완주율 (기존 제도 대비)

### 6.3 확장 가능성

**① 규제 이수 시장으로의 수직 확장 — 가장 유력한 사업화 경로**
KRX는 이미 **파생상품 → 개인 공매도 → 단일종목 레버리지** 순으로 동일 구조의 모의거래 이수제를 확장해 왔다. **"고위험 상품 출시 → 모의거래 이수 의무화"는 반복되는 규제 템플릿**이며, 상품이 추가될 때마다 우리 엔진의 시장은 넓어진다.
→ 확장 대상: 개인 공매도 · 파생상품 · ELS/DLS · 가상자산 · 채권

**② 상품군 확장**
자연어로 시장을 정의하는 구조이므로, 상품 추가는 *에셋 정의 + 시나리오 템플릿* 추가로 처리된다.

**③ 금융 외 영역 확장**
- **금융보안 훈련(주최기관 정합)** — 동일한 "AI 에이전트 + 시나리오 + 과정 채점" 엔진으로 **보이스피싱·스미싱 대응 훈련**을 구성할 수 있다. AI 에이전트가 사기범 페르소나를 연기하고, 사용자의 대응 행동을 채점해 **금융사기 대응 역량 인증**을 발급한다. *(대회 세부 주제 예시 중 "보이스피싱 등 이상금융거래 … AI 금융 보안 비서"와 직접 연결)*
- 보험 불완전판매 방지 교육, 대출·신용 관리 시뮬레이션
- 기업 내 컴플라이언스 훈련(내부통제 시나리오)

**④ 데이터 자산화**
가명 행동 로그의 집계 통계는 **"어떤 금융 개념이 실제로 학습되지 않는가"**에 대한 국내 최초 수준의 데이터셋이 된다. 감독 당국·연구기관 대상 리포트로 전환 가능.

## 7. 책임 있는 AI 설계 및 리스크 관리 *(자유 타이틀)*

> 주최기관이 **금융보안원**이라는 점을 고려해, 안전장치를 정면으로 다루는 항목으로 배치.
> "위험을 알고 설계했다"는 신호가 심사에서 감점 방어를 넘어 가점 요인이 된다.

| 리스크 | 대응 설계 |
|---|---|
| **생성 콘텐츠의 오남용** (가상 뉴스가 실제 정보로 오인) | ① 실존 기업·인물·티커 생성 차단 필터 ② 모든 생성물에 *"시뮬레이션 생성 콘텐츠"* 상시 라벨 ③ 외부 공유·다운로드 차단 ④ 가명 종목명은 실존 상호와 유사도 검사 |
| **모의투자의 도박화** | ① 수익률 랭킹 보드 미제공 ② 과정 점수만 공개 ③ 세션 시간 상한 및 휴식 안내 |
| **학습 전이 실패** (모의에서만 잘함) | ① 매 세션 시장 재생성으로 암기 방지 ② 사전/사후 개념 테스트로 이해도 직접 측정 |
| **인증의 오해** (사설 자격을 공인 자격으로 오인) | **"공인 자격이 아닌 학습 이수 증명"**임을 이수증 및 UI에 명시. KRX 이수제를 **대체가 아닌 보완**으로 포지셔닝 🔴 *팀 합의 필요 — '라이선스' 표현 대신 '이수증/역량 리포트' 권장* |
| **개인정보·금융정보 유출** | 실명·계좌·실보유종목 미수집. 유출되더라도 금융 피해가 성립하지 않는 데이터 구조 |
| **LLM 환각으로 인한 잘못된 금융 지식 전달** | 디브리핑의 교육 개념 설명은 **사전 검증된 지식 베이스에서 인용**하고, LLM은 사용자 로그에 맞춘 서술만 담당 (RAG 구조) |
| **서비스 가용성** (대회 결격 사유) | 심사 기간(9/7~9/11) 무중단 운영 계획 + 폴백 경로 확보 |

## 1. 서비스 명칭 *

> # Safe-T (세이프티)
> ## AI 레버리지 안전투자 훈련 플랫폼
> **"실제 돈을 잃기 전에, 고위험 상황을 먼저 겪고 판단력을 인증받는다"**

**영문 풀네임** — **S**imulated **A**I **F**inance **E**ducation & **T**raining
**발급 인증** — `INVEST PASS` (평가 시간별 등급, 예: `INVEST PASS L1 / 12-Minute Leverage & Volatility Assessment`)

## 2. 아이디어 기획 핵심내용(요약) *

> *(양식 요구: 전체 기획의 핵심 내용을 요약하여 **개조식**으로 간략히)*

- **한 줄 정의** — 실제 있었던 고위험 시장 구간을 **전면 가명화·정규화**해 60배속으로 재생하고, 사용자의 **투자 의사결정 과정을 100점으로 평가**해 교육 인증 `INVEST PASS`를 발급하는 AI 기반 모의투자 교육 플랫폼

- **문제** — 2026년 8월 19일부터 단일종목 레버리지 상품 신규 개인투자자에게 **모의거래 이수가 의무화**되었으나, 그 요건은 *'5거래일 × 1시간'* 이라는 **시간 충족 조건**일 뿐 **이해도를 측정하지 않는다.** 이수증은 발급되지만 학습은 검증되지 않는다.

- **해법 4단** —
  1. **성향 분석** : 투자 경험·위험 선호·레버리지 이해도·정보 검증 습관·**감수 가능한 위험 수준**을 설문으로 받아 AI가 강점·취약점·우선 학습 항목을 정리
  2. **맞춤 시나리오 배정** : AI가 **사전 검수된 시나리오 카탈로그 안에서** 사용자에게 필요한 구간을 선택. 시나리오는 실제 과거 시장 구간을 기반으로 하되 종목·기업·인물·날짜·뉴스 원문·절대 가격을 **전부 가명화**하고 시작가를 **랜덤 정규화**한다
  3. **가속 시장 관찰 및 판단** : 시장이 **60배속**으로 진행되며 공시·기사·커뮤니티 게시물이 실시간 등장. 시험은 **독립된 판단 문항 3개**로 구성되고, 사용자는 각 문항의 가명 자산에 대해 **UP / DOWN**을 선택하고, **판단 근거 태그(필수, 1개 이상)**와 **확신도(필수, 낮음·보통·높음)**를 함께 남긴다. 직접 입력 설명은 선택 사항이다. 복잡한 주문·비중·포지션 설정은 없다
  4. **과정 평가 및 인증** : 위험 신호 인식·정보 출처 구분·판단과 근거의 일관성 등 **7개 항목 100점**을 문항마다 채점하고, **세 문항의 평균이 70점 이상이면 `INVEST PASS`를 발급**한다. 항목 점수는 LLM이 생성하되 **범위 검증·합계·평균·통과 판정은 규칙 코드**가 수행한다

- **핵심 설계 원칙 4가지**
  - **AI는 시장을 만들지 않는다.** 가격·거래량·수급은 실제 히스토리를 재생하며, AI는 성향 분석·시나리오 선택·콘텐츠 각색·행동 해석만 담당한다
  - **수익률과 방향 적중률을 계산·표시·채점하지 않는다.** 응답 후 흐름은 판단 과정의 효용을 설명하는 문맥으로만 사용한다
  - **최종 점수와 합격은 규칙 기반 엔진이 결정한다.** 동일 시나리오·동일 판단 기록에는 동일 점수가 나와야 한다
  - **포지션·비중·손익을 계산하지 않는다.** UP/DOWN은 방향 의견이며 가상 보유량이나 수익률로 변환하지 않는다

- **차별성 한 줄** — 기존 모의투자가 *"실전 주문 화면에 익숙해지는 곳"*이라면, Safe-T는 *"실전에서 잃을 돈을 미리 잃고, 왜 잃었는지 진단받고, 그 역량을 인증받는 곳"*

- **활용처** — ① 고위험 상품 신규 진입 개인투자자(B2C) ② 증권사·거래소의 투자자보호 이수 프로그램(B2B) ③ 학교·기관 금융교육(B2G)

## 3. 문제 정의 및 제안 배경 *

> *(양식 요구: 구체적 문제점 + **특정 금융 고객**과 **채널**을 선택한 배경·이유)*

### 3.1 배경 — 2026년, 규제가 상품을 따라잡는 데 84일이 걸렸다

| 시점 | 사건 |
|---|---|
| 2026-05-27 | 삼성전자·SK하이닉스 기초 **단일종목 레버리지·인버스(2×) ETF 상장** |
| ~ 2026-06-19 | 개인투자자 누적 순매수 **약 8.2조 원** |
| 2026-06-23 | 시장 급락 → 해당 ETF 14종 **하루 평균 -25.05%** |
| 2026-08 중순 | 일간 거래대금 10조 원대 → **1조 원대 이하 급감** |
| **2026-08-19** | **신규 개인투자자 모의거래 이수 의무화 시행** |

동시에 국내 금융소비자의 **디지털 금융이해력은 59.3점**으로 OECD 목표(70점)를 밑돌고, 조사대상의 **70% 이상이 저이해력 집단**에 속한다. 같은 조사는 **금융서비스 이용 경험이 이해력을 2.2~3.5점 끌어올린다**고 보고한다. → **경험이 이해를 만든다. 그러나 그 경험은 실제 돈으로 사서는 안 된다.**

### 3.2 문제 정의 — 3층 구조

**P1. 상품 위험도와 투자자 이해도의 격차**
레버리지·인버스는 **일간 수익률 배수 추종**으로 인해 **변동성 잠식(volatility decay)**이 발생하며, 횡보장에서도 원금이 녹는다. 이 개념은 텍스트 교육으로는 거의 전달되지 않는다. *체감해야만 이해되는 위험*이다.

**P2. 이수 제도가 "시간"만 측정하고 "이해"를 측정하지 않는다**

| 현행 이수 요건 | 측정하는 것 | 측정하지 않는 것 |
|---|---|---|
| 총 5거래일 이상 접속·거래 | 접속 일수 | 손실 상황에서의 의사결정 |
| 매 거래일 1시간 이상 | 체류 시간 | 리스크 개념의 이해 여부 |
| HTS 설치 후 정규장/Replay장 이용 | 주문 실행 능력 | 왜 그 주문을 냈는지 |

→ **창을 띄워놓기만 해도 이수증이 발급되는 구조.** 제도의 취지("리스크를 명확히 인지하고 투자")와 실행 사이에 공백이 있다.

**P3. 기존 모의투자 서비스는 학습을 만들지 못한다**

| # | 한계 | 결과 |
|---|---|---|
| C1 | **실제 종목명·실제 날짜를 그대로 노출** | 어떤 구간인지 아는 순간 **정답을 검색**할 수 있다 |
| C2 | 수익률 랭킹 중심 | **몰빵한 사람이 1등** — 잘못된 행동을 강화 |
| C3 | 전원 동일 시나리오 | 개인의 취약점(위험 한도 초과, 정보 미검증)을 겨냥하지 못함 |
| C4 | 이수 후 피드백 없음 | 무엇을 왜 잘못했는지 모른 채 종료 |
| C5 | 진입 장벽이 높음 | HTS 설치와 복잡한 주문 화면이 학습 이전에 이탈을 만든다 |

### 3.3 타깃 금융 고객 (선택 배경) 🔴 *팀 확정 필요*

**1차 타깃 — 고위험 상품에 신규 진입하려는 20~30대 개인 일반투자자**
- **선택 이유 ①** 2026-08-19 이수 의무화의 **법적 대상자**와 정확히 일치 → 제도가 이미 수요를 만들어 두었다
- **선택 이유 ②** 대회 세부 주제 예시 중 *"청년층 자산 형성 … AI 기반 포용적 금융서비스"*에 직접 부합
- **선택 이유 ③** 투자 경험이 짧아 **손실 경험의 학습 비용이 가장 비싼** 집단

**2차 타깃(B2B) — 증권사·거래소의 투자자보호/교육 담당 부서**
- 이수 프로그램을 운영해야 하지만 **역량 측정 수단이 없는** 주체

### 3.4 채널 선택 (선택 배경)

**모바일 웹(Mobile-first Web) 우선 — 데스크톱 반응형 지원**

| 근거 | 설명 |
|---|---|
| **제도-현실 불일치 해소** | 현행 KRX 모의거래는 **HTS 전용이며 MTS(모바일) 불가**. 그러나 20~30대 개인투자자의 실제 거래 채널은 압도적으로 모바일이다. **"모바일에서 배우고 모바일에서 거래한다"**는 채널 일치가 학습 전이(transfer)를 만든다 |
| **접근 마찰 최소화** | 설치·인증서 없이 URL 하나로 진입. 주문 대신 **UP/DOWN 두 가지 선택**만 요구하므로 투자 경험이 없는 사용자도 즉시 참여 가능 → 포용적 금융의 전제 |
| **대회 요건 정합** | 심사는 **배포 URL로 진행**된다. 웹이 곧 제출물 |

## 4. 서비스 컨셉 및 차별성 *

### 4.1 서비스 컨셉 — "실제 있었던 위기를, 이름만 지우고 다시 겪는다"

```
 성향 설문 → AI 성향 분석 → 맞춤 시나리오 배정 → 60배속 시장 관찰
   → 자산별 UP/DOWN 판단 → 과정 중심 평가 → AI 분석 보고서 → INVEST PASS
```

**① 성향 분석**
투자 경험, 위험 선호도, **레버리지 이해도**, 손실 대응 성향, **정보 출처 검증 습관**, 관심 자산, **평가 시 감수 가능한 위험 수준**을 받아 AI가 성향 요약·강점·취약점·우선 학습 항목·적합 시나리오를 산출한다.

**② 맞춤 시나리오 배정 — AI는 선택하고, 생성하지 않는다**
AI는 **사전에 검수된 시나리오 카탈로그 안에서만** 선택한다. 각 시나리오는 실제 과거 시장 구간을 기반으로 제작하되 다음을 전부 가명화한다.

> 종목명 · 기업명 · 인물명 · 날짜 · 뉴스 제목과 본문 · 절대 가격

가격은 시작 시점 기준으로 정규화하며, 시작값을 랜덤화한다.

```
정규화 가격 = 실제 가격 / 시작 가격 × 100  (시작값은 랜덤 가중)
```

시험은 **서로 독립된 판단 문항 3개**로 구성되며, 각 문항은 하나의 가명 자산과 그 시점의 시장을 제시한다.

> 🔴 **PoC 범위 (2026-09-03 기준)** — 현재 구현 명세상 PoC 시나리오에는 **레버리지·인버스 상품을 포함하지 않는다.**
> PoC는 레버리지 위험의 본질인 **고변동 구간에서의 판단**을 일반 자산으로 먼저 훈련시키고,
> 레버리지 상품은 상품 유형·배수를 명시하는 시나리오 스키마 확장 이후 편입한다. → 6번 확장 계획 참조.
> 레버리지 개념 자체는 이번 PoC에서 **온보딩 설문 응답**으로만 확인한다.

시나리오는 가격 OHLC, 거래량, **개인·외국인·기관 매매 동향**, 관련 뉴스와 공시, 커뮤니티 게시물, 변동성 이벤트, **금·채권·환율·비트코인 등 참고지표**, 시나리오별 평가 규칙을 포함한다.

**③ 가속 시장과 판단 기록**
시장은 **실제 시간의 60배속**(서비스 1분 = 시장 60분)으로 **서버 시간 기준** 진행된다. 사용자가 화면을 벗어나도 시장과 이벤트는 계속 흐르고, 재접속하면 현재 시점부터 이어서 참여한다.

문항은 **순서가 고정된 3개**이며 **한 번에 하나만 공개**된다. 이전 문항의 의견은 다음 문항으로 이어지지 않는다. 각 문항에는 제한 시간 안에 UP/DOWN을 **최소 한 번 제출**하며, 시장이 진행되는 동안 수시로 다시 제출할 수 있다. 매 입력은 이전 응답을 변경하거나 덮어쓰지 않고 시간순 판단 이벤트로 누적된다.

판단 이벤트가 한 건 이상인 문항은 **`ANSWERED`로 LLM 채점 대상**이 된다. 한 건도 없는 문항은 `UNANSWERED`로 **0점**이다. `ANSWERED`이면 제한 시간 전에 **`문항 완료/다음`**으로 이동할 수 있고, 별도의 **`시험 종료`**로 언제든 조기 종료할 수 있다. **두 행위 모두 고정 감점이 없다.**

모든 선택은 다음과 함께 기록된다.

> 선택 방향 · 필수 확신도 · 필수 판단 근거 태그 · 선택적 직접 입력 · 선택 시각 · 당시 시장 시점과 가격 · **열람한 뉴스와 출처(타임스탬프 포함)**

**④ 과정 평가 — 결과가 아니라 판단 과정을 채점한다**

평가에서 말하는 판단의 효용은 **가격을 맞혔는지가 아니다.** 응답 당시 이용 가능했던 제한된 정보에서 근거를 선택하고 확신도를 표현하며, 방향·근거·확신도가 서로 일관되어 **충동적 판단을 줄이는 데 도움이 되는지**를 본다.

답변한 각 문항을 **100점 만점**으로 다음 항목에 따라 평가한다.

| 평가 항목 | 배점 | 판단 증거 |
|---|---:|---|
| 위험 신호 인식과 대응 | 20 | 변동성·거래량·뉴스의 위험 신호를 응답 근거에 반영했는지 |
| 불확실성과 변동성 인식 | 15 | 당시 정보의 불확실성과 가격 변동성을 판단 태그·확신도에 반영했는지 |
| 정보 활용과 출처 구분 | 15 | 시나리오 설명과 가명 뉴스의 역할을 구분하고 필요한 상세 정보를 열람했는지 |
| 시장 흐름 해석 | 15 | 당시 공개된 캔들·거래량·사건을 UP/DOWN 판단과 연결했는지 |
| **초기 성향과 응답의 정합성** | 15 | 설문에서 밝힌 정보 활용·위험 인식 성향과 실제 응답이 어떻게 이어지는지 |
| 판단·확신도·근거의 일관성 | 10 | UP/DOWN, 확신도, 선택한 태그와 직접 설명이 서로 모순되지 않는지 |
| 판단 근거의 유용성 | 10 | 선택한 근거가 당시 의사결정에 실질적으로 유용하고 서로 모순되지 않는지 |
| **합계** | **100** | |

**총점과 통과 조건**

```
최종 점수 = (문항1 점수 + 문항2 점수 + 문항3 점수) / 3
반올림 전 최종 점수가 70 이상이면 PASS
```

- 미응답 문항은 **정확히 0점**이며, 이 판정은 LLM 추론이 아니라 **결정론적 규칙**이다
- 문항 조기 완료와 시험 조기 종료 **자체에는 고정 감점이 없다**
- 항목 점수는 LLM이 **Snapshot에 기록된 당시 공개 정보와 판단 과정만** 사용해 생성하고, **규칙 코드가 범위와 합계를 검증**한다
- LLM 출력이 누락되거나 범위를 벗어나면 **임의로 보정하지 않고 실패로 거부**한 뒤 버전이 기록된 재시도 정책을 적용한다
- `(snapshotHash, rubricVersion, promptVersion, modelVersion)`이 같은 재요청은 **저장된 동일 결과를 반환**한다 → 재현성 확보

> **배점표 전체가 "관찰 가능한 행동"으로 구성되어 있다.** 포지션·수익률·집중도처럼 PoC가 계산하지 않는 값에 의존하는 항목이 없다.

**채점 기준은 사전에 공개한다.** 평가 시작 전 위 7개 항목과 배점을 안내해, 사용자가 *"수익률이 아니라 판단 과정이 평가된다"*는 것을 알고 시작하도록 한다. 채점 기준은 불변 버전(`rubricVersion`)으로 관리되며 평가 결과에 함께 기록된다.

> 이는 교육 효과와 설명가능성을 동시에 얻기 위한 설계다. 기준을 모르고 시작하면 여전히 **방향 맞히기 게임**이 되고, 기준이 공개되지 않으면 *"AI가 임의로 점수를 매긴다"*는 의심을 남긴다.

### 4.2 기존 금융 앱 대비 차별성 (5)

| # | 차별성 | 기존 서비스 | Safe-T |
|---|---|---|---|
| **D1** | **전면 가명화·정규화된 실제 시장** | 실제 종목명·날짜 그대로 → 검색으로 결과 확인 가능 | 종목·기업·인물·날짜·뉴스 원문·절대 가격을 전부 가명화하고 시작가를 정규화. **검색 단서가 남지 않는다.** 동시에 실제 사건의 **인과 구조는 보존**되어 합성 데이터보다 학습 전이가 높다 |
| **D2** | **과정 채점 + 통과 기준** | 수익률 랭킹 → 몰빵이 1등 | 7개 항목 100점, **70점 통과**. 수익률·방향 적중률은 계산하지 않음 → **운으로 통과할 수 없다** |
| **D3** | **개인 맞춤 시나리오 배정** | 전원 동일 | 성향 분석 결과로 **약점을 겨냥한 구간**을 검수된 카탈로그에서 배정 |
| **D4** | **판단·확신도·근거를 함께 기록하고 대조한다** | 결과만 기록 | 방향·**확신도**·**근거 태그**를 필수로 남기고 직접 설명은 선택할 수 있다. **뉴스가 화면에 노출된 사실과 실제로 열어본 사실을 구분해** 기록한다. → *"근거로 '뉴스'를 선택하셨지만 상세 본문을 연 적은 없습니다"* — **자기 인식과 실제 행동의 괴리 자체를 진단한다** |
| **D5** | **AI 분석 보고서 + 교육 인증** | 피드백 없음, 시간 기반 이수 | 자연어 보고서 + **`INVEST PASS`** — 시간 기반 이수 제도의 형식성을 역량 기반으로 보완 |

> **왜 이것이 독창적인가**
> 시중의 금융 AI는 대부분 **"AI가 더 잘 투자하게 만드는"** 방향이다.
> Safe-T는 반대로 **"AI가 사람을 더 잘 판단하게 훈련시키는"** 방향이다.
> AI는 시장을 만들지 않는다. **성향을 읽고, 상황을 각색하고, 판단을 해석한다.**

### 4.3 Safe-T가 하지 않는 것 (스코프 방어)
- 실제 종목에 대한 **투자 자문·추천·수익률 예측을 하지 않는다** → 투자자문업 규제 회피 및 서비스 철학 일관성
- 실제 주문 체결·자금 이동 없음 → 금전 리스크 0
- **수익률 랭킹 보드를 만들지 않는다** → 게임화의 도박화 전이 차단
- **AI가 시장 가격이나 무한 시나리오를 자유 생성하지 않는다** → 재현성 확보 및 교육적 신뢰성

## 5. 활용 데이터 및 생성형 AI 모델 적용 방안 *

> *(양식 요구: 데이터 종류·수집·활용 방안 + **생성형 AI가 서비스 내에서 수행하는 역할을 구체적으로**)*

### 5.1 활용 데이터

| 구분 | 데이터 | 수집·가공 방안 | 활용 |
|---|---|---|---|
| **시장 히스토리** | **1분봉 OHLCV** (문항 구간 180분 + 사전 60분) | **글로벌 가상자산 거래소의 공개 아카이브**(Binance Spot·Bitstamp Spot)에서 실제 과거 구간을 수집. 재수집·검증 스크립트로 행 수·시간축·OHLC 정합·해시를 확인 | 시나리오의 원본. **AI가 생성하지 않고 그대로 재생** |
| **뉴스·공시** | 원 제목, 정확한 UTC 시각, 출처 URL, **독자적으로 작성한 사실 요약** | **원문 전문은 저장하지 않는다.** 시각 근거(공시 표기·게시 ID)를 함께 기록 | 가명 합성 콘텐츠의 사실 기반 |

| **시나리오 카탈로그** | 시나리오 정의, 이벤트 타임라인, 시나리오별 평가 규칙 | **사람이 사전 검수**해 고정 | AI가 이 안에서만 선택 |
| **사용자 성향 데이터** | 투자 경험, 위험 선호, 레버리지 이해도, 정보 검증 습관, **감수 가능 위험 수준** (10문항) | 온보딩 설문 | 시나리오 배정 + **채점 기준선** |
| **판단 로그** | 선택 방향, 필수 근거 태그·확신도, 선택적 자유 텍스트, 선택 시각, 당시 시장 시점·가격, **열람한 정보와 출처(타임스탬프 포함)** | 서비스 자체 생성 | 과정 채점, **자기신고 근거 vs 실제 열람 대조**, AI 분석 보고서 |

**시장 데이터 선택 근거 — 왜 이 구간들인가**

훈련 소재는 **자산군이 아니라 상황**이다. 사용자에게는 종목명·티커·날짜·절대 가격이 모두 가명화·정규화되어 제시되므로, 원본이 어떤 시장이었는지는 드러나지 않는다. 선택 기준은 다음 세 가지였다.

| 기준 | 이유 |
|---|---|
| **고변동 구간이 실재할 것** | 급락·급등·유동성 증발 등 *판단이 시험되는 상황*이 실제로 일어난 구간이어야 훈련이 성립한다 |
| **1분 단위 연속 데이터** | 60배속 재생과 180분 고정 판정 구간을 만들려면 조밀한 시계열이 필요하다 |
| **공개 아카이브 + 명확한 이용 조건** | 재수집·검증이 가능하고, 라이선스 리스크가 낮아야 한다 |

수집한 10개 구간은 **거시 충격(금리·물가 발표), 규제·공시 이벤트, 유동성 위기, 허위 정보 유포** 등 서로 다른 사건 유형으로 구성했다. 이는 배점 항목인 **정보 출처 검증**과 **급변 구간 대응**을 각각 다른 방식으로 시험하기 위한 것이다.

> 학습되는 역량(정보 출처를 구분하는가 · 급변에 어떻게 반응하는가 · 근거 있는 판단을 하는가)은 **자산군에 종속되지 않는다.**
> 향후 국내 주식·레버리지 ETF 구간을 시나리오 카탈로그에 추가할 때도 **엔진 변경 없이 편입**된다. → 6번 확장 계획

**개인정보 처리 방침 (설계 원칙)**
- **실명·주민번호·계좌번호·실제 보유종목·실제 자산 규모를 일절 수집하지 않는다** (스펙 비기능 조건)
- 로그인은 익명 세션 또는 이메일 단일 식별자
- 판단 로그는 **서비스 내부에서 생성된 가상 판단 기록**이므로 금융거래정보에 해당하지 않는다
- → **민감정보 미처리. 유출되더라도 금융 피해가 성립하지 않는 데이터 구조** *(주최기관 금융보안원의 관점에서 유의미한 설계 선택)*

### 5.2 생성형 AI 적용 방안 — 5개 역할과 그 경계

| # | AI 역할 | 입력 | 출력 | 왜 LLM이어야 하는가 |
|---|---|---|---|---|
| **A. 성향 분석** | 설문 응답 → 강점·취약점·학습 항목 | 10문항 응답 | 성향 요약, 강점, 취약점, 우선 학습 항목 | **자기 응답 간의 모순**(예: "대략 안다"고 했으나 변동성 잠식 오답)을 짚어내는 것은 규칙으로 열거하기 어렵다 |
| **B. 시나리오 배정** | 성향 프로파일 → 시나리오 선택 | 프로파일 + **검수된 시나리오 카탈로그** | 시나리오 ID + 배정 근거 | 취약점과 시나리오 특성의 **의미적 매칭**. 단, **카탈로그 밖으로 나가지 않는다** |
| **C. 콘텐츠 각색** | 시나리오 사실 → 가명 공시·기사·커뮤니티 글 | 시나리오에 정의된 사실, 현재 진행 시점 | 공시 / 언론 기사 / 익명 커뮤니티 게시물 | 동일 사건을 **출처별 서로 다른 어조와 신뢰도**로 재구성해야 정보 출처 검증(15점)을 채점할 재료가 생긴다 |
| **D. 행동 분석 및 이유 평가** | 판단 로그 → 패턴·근거 | 세 문항의 전체 판단 이벤트, 정보 열람 이력 | 문항별 판단 시점·방향 전환·확신도와 근거 변화, 성향과 실제 행동의 정합성, **당시 공개 정보와 선택 근거의 연결** | 시간순 판단·태그·선택적 문장·열람 행동을 함께 해석해야 한다 |
| **E. 결과 보고서** | 항목별 점수 + 로그 | 자연어 보고서 | 잘한 행동, 위험 행동, 개선 방향 | 정량 지표를 **개인의 언어로 설명**해야 행동이 바뀐다 |

**AI가 담당하지 않는 영역 (스펙 명시)**

| 영역 | 처리 주체 | 이유 |
|---|---|---|
| 캔들 및 시장 데이터 생성 | 실제 히스토리 재생 | 인과 구조 보존, 재현성 |
| 시장 시간 진행 | 서버 스케줄러 | 결정적 진행 |
| **최종 점수 계산** | **규칙 기반 평가 엔진** | 동일 입력 → 동일 점수 |
| **합격 여부 결정** | **규칙 기반 임계값(70점)** | 자의성 배제 |

**시스템 경계 — LLM은 중앙 엔진 밖에 있다**

중앙 엔진은 모델 API·SDK·프롬프트를 갖지 않는다. 엔진은 **시나리오 재생 · 행동 기록 · 평가 입력 봉인**만 수행하고, LLM은 그 앞뒤의 독립된 단계에서 동작한다.

```
[시나리오 제작 LLM]  실제 뉴스의 확인된 사실 → 가명 합성 콘텐츠   (+ 사람 검수 승인)
        ↓
[선택 LLM]           설문 원본 → 게시 후보 중 문항 3개 선택
        ↓
   ◆ 중앙 엔진 ◆     재생 · 기록 · 불변 Snapshot 봉인 (LLM 없음)
        ↓
[평가 LLM]           봉인된 Snapshot → 항목별 점수와 근거
        ↓
   결정적 결과 서비스  미응답 문항 0점 · 총점 · 합격 판정
```

이 분리가 만드는 것 — ① 평가 입력이 **봉인·해시**되어 사후 변경이 불가능하고 ② 채점의 **버전(rubric·prompt·model)이 기록**되며 ③ 판단 시점 이후 정보가 평가 입력에서 **제외**된다.

### 5.3 콘텐츠 생성 원칙 (스펙 준수)

- 실존 기업·인물·종목명 사용 금지
- 실제 뉴스 원문 복사 금지
- **시나리오에 정의된 사실만 사용**
- 시나리오상 **미래 데이터는 모르는 채로**, 현재 진행 상황만 기반으로 생성
- 동일 시나리오 안에서 **가명 일관성 유지**
- 모든 콘텐츠에 **`AI 생성 시뮬레이션 콘텐츠`** 표시
- 실제 투자 추천 문구 생성 금지

### 5.4 모델 운용

- **온프레미스 우선:** 자체 서버에 오픈 웨이트 모델 서빙 — 비용 통제 및 **데이터 외부 반출 없음** 🔴 *정확한 모델 ID 확인 필요*
- **역할별 분리:** C(콘텐츠 각색)는 시나리오 제작 시 **사전 배치 생성 후 검수**해 캐시. A·B·D·E는 평가 전후 1회씩 호출 → **평가 진행 중 LLM 호출이 없어 지연·비용이 통제된다**
- **재현성:** 평가 입력 Snapshot을 **RFC 8785 정규화 후 SHA-256으로 봉인**하고, `snapshotHash`·`rubricVersion`·`promptVersion`·`modelVersion`과 출력 해시를 함께 보존한다. 총점·합격 판정은 결정적 규칙이 산출한다
- 🔴 **가용성:** 배포 URL은 **9/7 11:00 ~ 9/11 23:59 무중단 접속 필수(불가 시 결격)**. 평가 상태가 서버에 저장되므로 세션 지속성까지 함께 보장해야 한다

## 6. 기대 효과 및 확장 가능성 *

### 6.1 해결하는 문제와 기대 효과

| 대상 | 기대 효과 |
|---|---|
| **개인투자자** | 실제 손실 없이 **변동성 잠식·급락 구간의 판단 실패**를 체감. 자신의 판단 습관을 **점수와 근거로 통보받는 최초의 경험** |
| **증권사·거래소** | 시간 기반 이수제를 **역량 기반(`INVEST PASS`)으로 보완**할 수 있는 측정 도구 확보. 투자자보호 의무 이행의 실질화 |
| **감독 당국** | 이수자의 **집계 행동 데이터**를 통해 "어떤 개념이 실제로 이해되지 않는가"를 최초로 정량 파악 |
| **학교·기관** | 교사가 자연어로 시장을 만들어 배포하는 **금융교육 교보재** |

### 6.2 효과 측정 지표

Safe-T는 **모든 판단을 로그로 남기므로, 교육 효과를 서비스 자체가 측정한다.** 별도 조사 없이 다음 지표가 사용자 수 증가와 함께 축적된다.

| 지표 | 산출 방법 | 무엇을 증명하는가 |
|---|---|---|
| **총점 향상폭** | 동일 사용자의 1회차 대비 N회차 총점 | 반복 훈련의 학습 효과 |
| **초기 성향과 행동의 정합성 변화** | 설문에서 밝힌 정보·위험 성향과 실제 열람·판단의 정합성 | 자기 인식과 실제 행동의 간극 개선 |
| **근거 활용 개선폭** | 무열람 판단 비율과 근거·확신도 불일치 감소 | 근거 중심 판단 습관의 개선 |
| **정보 출처 검증 행동 변화** | 공시 열람 비율, 무열람 판단 비율 | 행동 변화의 직접 증거 |
| 평가 완주율 · `INVEST PASS` 통과율 | 세션 로그 | 제도 이수율(형식적 완주) 대비 실질 통과율 |

> 이 지표들은 **감독 당국과 금융사가 지금까지 갖지 못한 데이터**다.
> 현행 이수 제도는 접속 시간만 기록하므로 *"이수자가 무엇을 이해하지 못하는가"*를 알 수 없다.
> Safe-T는 그 질문에 답할 수 있는 최초의 측정 도구가 된다.

🟡 *PoC 단계에서는 실사용 데이터가 없으므로, 위 지표는 **측정 설계**로 제시하고 실측치는 제시하지 않는다.*

### 6.3 확장 가능성

**① 규제 이수 시장으로의 수직 확장 — 가장 유력한 사업화 경로**
KRX는 이미 **파생상품 → 개인 공매도 → 단일종목 레버리지** 순으로 동일 구조의 모의거래 이수제를 확장해 왔다. **"고위험 상품 출시 → 모의거래 이수 의무화"는 반복되는 규제 템플릿**이며, 상품이 추가될 때마다 우리 엔진의 시장은 넓어진다.
→ 확장 대상: 개인 공매도 · 파생상품 · ELS/DLS · 가상자산 · 채권

**② 레버리지 상품 편입 — 가장 가까운 후속 개발**

PoC는 고변동 구간에서의 **판단 능력**을 일반 자산으로 먼저 훈련시킨다. 다음 단계는 시나리오에 **레버리지·인버스 상품을 편입**하는 것이다. 상품 유형과 배수를 명시하는 시나리오 스키마 확장이 선행되며, 이후 다음이 가능해진다.

- **변동성 잠식의 직접 체감** — 기초자산이 제자리로 돌아온 구간에서 레버리지 상품만 손실이 남는 경험
- 「레버리지 통제」를 자기신고가 아니라 **실제 판단 행동**으로 측정
- 2026-08-19 이수 의무화 대상 상품과 **1:1 대응하는 훈련 과정** 제공

> 문제 정의(3번)가 겨냥한 지점에 정확히 도달하는 단계이며, **B2B 제안의 전제**이기도 하다.

**③ 실전형 모드 — 포지션과 비중을 다루는 고도화**
이번 PoC는 **캐주얼 판단 모드**(UP/DOWN)로 범위를 좁혔다. 동일한 성향 분석·시나리오 배정·과정 채점·보고서 엔진 위에 **가상 자금 기반 실전형 모의투자 모드**를 얹는 것이 다음 단계다.

| | 캐주얼 판단 모드 (PoC) | 실전형 모드 (후속) |
|---|---|---|
| 액션 | UP / DOWN + 근거 | 매수·매도·비중 조절·손절 |
| 상태 | 포지션·비중·손익 **없음** | 가상 포지션·잔고·손익 |
| 추가 채점 항목 | — | 포지션 사이징, 손절 준수율, 자산 집중도, 최대 낙폭 |
| 시장 | 히스토리 재생 | 재생 + **AI 에이전트 시장 참여자**(슬리피지·유동성 증발 재현) |

캐주얼 모드는 실전형의 축소판이 아니라, 실전형에서도 필요한 **성향 분석 · 시나리오 배정 · 판단 기록 · 과정 평가 · AI 보고서 · 인증 발급**을 먼저 검증하는 핵심 서브셋이다. 동시에 복잡한 주문 없이 누구나 참여할 수 있어 **대중 대상 위험투자 교육 모드로도 독립적 가치**를 갖는다.

**④ 상품군 확장**
시나리오 카탈로그에 구간을 추가하는 것만으로 시장 상황이 늘어난다. 엔진 변경이 필요 없다.

**⑤ 금융 외 영역 확장**
- **금융보안 훈련(주최기관 정합)** — 동일한 "성향 분석 + 시나리오 배정 + 과정 채점 + AI 보고서" 엔진으로 **보이스피싱·스미싱 대응 훈련**을 구성할 수 있다. AI 에이전트가 사기범 페르소나를 연기하고, 사용자의 대응 행동을 채점해 **금융사기 대응 역량 인증**을 발급한다. *(대회 세부 주제 예시 중 "보이스피싱 등 이상금융거래 … AI 금융 보안 비서"와 직접 연결)*
- 보험 불완전판매 방지 교육, 대출·신용 관리 시뮬레이션
- 기업 내 컴플라이언스 훈련(내부통제 시나리오)

**⑥ 데이터 자산화**
가명 판단 로그의 집계 통계는 **"어떤 금융 개념이 실제로 학습되지 않는가"**에 대한 국내 최초 수준의 데이터셋이 된다. 감독 당국·연구기관 대상 리포트로 전환 가능.

> "위험을 알고 설계했다"는 신호가 심사에서 감점 방어를 넘어 가점 요인이 된다.

| 리스크 | 대응 설계 |

| **채점의 자의성·비재현성** | 최종 점수와 합격 여부를 **규칙 기반 엔진**이 결정. 동일 시나리오·동일 판단 기록에 동일 점수. 시나리오·평가 규칙·AI 프롬프트 **버전을 기록** |
| **개인정보·금융정보 유출** | 실명·계좌·실보유종목 미수집. 유출되더라도 금융 피해가 성립하지 않는 데이터 구조 |
| **LLM 환각으로 인한 잘못된 금융 지식 전달** | 교육 개념 설명은 **사전 검증된 지식 베이스에서 인용**하고, LLM은 사용자 로그에 맞춘 서술만 담당. 생성 콘텐츠는 **시나리오에 정의된 사실만** 사용 |
| **서비스 가용성** (대회 결격 사유) | 심사 기간(9/7~9/11) 무중단 운영 + **평가 상태 서버 저장으로 재접속 이어하기 보장** + 폴백 경로 확보 |
| **채점 기준의 불투명성** | 각 평가 항목의 관찰 증거와 점수화 규칙을 **평가 증거 계획(rubric)** 으로 외부에 명문화하고 버전을 고정한다. 엔진은 그 참조의 **불변성만 검증**하고 의미를 해석하지 않는다 🔴 *rubric 작성이 선행 과제* |
| **원본 데이터의 저작권·이용 조건** | ① 시장 데이터는 **공개 아카이브**에서 수집하고 재수집·검증 스크립트로 무결성을 확인한다 ② **뉴스 원문 전문을 저장하지 않는다** — 원 제목·URL·시각과 **독자적으로 작성한 사실 요약**만 보관한다 ③ 서비스에 반영되는 것은 **가명화·정규화를 거친 결과물**이며 제작 도구와 정규화 정책의 버전을 기록한다 |
| **가명화 이전 원본의 노출** | 원본 데이터셋은 실제 자산·시점·절대 가격·출처 URL을 보존하므로 **참가자에게 노출되어서는 안 된다.** 공개 배포본에는 **가명화·정규화가 적용된 패키지만** 반영하고, 실제 자산·시점을 추론할 수 있는 메타데이터를 제거한다 🔴 *제출 배포본에서 반드시 확인* |

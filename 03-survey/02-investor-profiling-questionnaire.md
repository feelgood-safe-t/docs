# 설문 ② 투자 성향 분석 문항 — 서비스 온보딩 내장용

> **근거:** `spec/README.md` §PoC 기능 범위 → 사용자 성향 분석
> **목적:** 성향을 분석해 ① **검수된 시나리오 중 맞춤 배정** ② **평가 채점의 기준선 확보**
> **분량:** 10문항 · 약 80초 · 진행률 바 표시
> **설계 원칙:** 모든 문항이 **시나리오 배정** 또는 **채점 기준선**으로 직접 쓰여야 한다. 장식용 문항 금지.

---

## 스펙이 요구하는 7개 항목과의 매핑

| spec 요구 항목 | 문항 | 쓰임 |
|---|---|---|
| 투자 경험 | A1, A2 | 시나리오 난이도 |
| 위험 선호도 | B1 | 시나리오 변동성 강도 |
| **레버리지 이해도** | **C1, C2** | 시나리오 레버리지 비중 · 기초 개념 퀴즈(5점) 난이도 |
| 손실 대응 성향 | B2 | 시나리오 낙폭 구간 설계 |
| **정보 출처 검증 습관** | **D1, D2** | **정보 출처 검증 채점(15점)** 기준선 |
| 관심 자산 및 산업 | E1 | 가명 자산의 섹터 프로파일 |
| **평가 시 감수 가능한 위험 수준** | **F1** | **위험 한도 준수 채점(20점)** 기준선 |

> **F1이 없으면 최대 배점 항목(20점)을 채점할 수 없다. 축소하더라도 F1은 반드시 유지한다.**

## 온보딩 인트로 카피

```
시장을 배정하기 전에, 당신을 먼저 알아야 합니다.

10개 질문에 답하면
AI가 당신에게 맞는 시장 상황을 골라 드립니다.

정답은 없습니다. 솔직할수록 정확해집니다.
```

**버튼:** `시작하기` · 하단 보조문구: `약 80초 소요 · 실명·계좌 정보는 수집하지 않습니다`

---

## SECTION A. 투자 경험 (2문항)
> → 시나리오 난이도, 기초 개념 안내 수준

**A1. 투자 경험이 어느 정도인가요?**

| 선택지 | 매핑 |
|---|---|
| 아직 해본 적 없어요 | `experience=none` · 튜토리얼 강제 · 이벤트 밀도↓ |
| 1년 미만 | `basic` |
| 1~3년 | `standard` |
| 3년 이상 | `advanced` · 이벤트 밀도↑ |

**A2. 다음 중 거래해 본 상품을 모두 골라주세요.** *(복수선택)*
`국내주식 / 해외주식 / ETF / 레버리지·인버스 ETF·ETN / 파생상품 / 가상자산 / 없음`
→ **레버리지 미경험자는 레버리지 자산이 포함된 시나리오를 우선 배정**한다. (제도상 이수 의무 대상과 동일한 집단)

---

## SECTION B. 위험 선호도 및 손실 대응 (2문항)
> → 시나리오의 변동성 강도와 낙폭 구간

**B1. "원금 손실 가능성이 없다면 수익률이 낮아도 괜찮다"**
`전혀 아니다 1 ─ 2 ─ 3 ─ 4 ─ 5 매우 그렇다`
→ `risk_appetite` (1~5). 낮을수록 고변동성 시나리오 배정

**B2. 투자한 자산이 하루 만에 -20%가 되었습니다. 첫 반응은?**

| 선택지 | 프로파일 태그 |
|---|---|
| 즉시 전부 정리한다 | `panic_exit` |
| 일부만 정리하고 지켜본다 | `balanced` |
| 그대로 둔다 | `hold_bias` |
| **더 늘린다** | `chase_down` ← **하락 지속 시나리오 우선 배정** |

→ 평가 항목 **「손실 이후 행동」(10점)**의 기준선

---

## SECTION C. 레버리지 이해도 (2문항) — **스펙 신규 요구**
> → 레버리지 자산 비중 결정 + **기초 개념 퀴즈(5점)** 난이도 보정

**C1. 다음 문장이 맞다고 생각하시나요?**
> **"기초자산이 한 달 뒤 제자리로 돌아오면, 2배 레버리지 상품도 대체로 제자리로 돌아온다."**

`그렇다 / 아니다 / 잘 모르겠다`
→ **정답은 '아니다'**(변동성 잠식). 오답 시 `leverage_literacy=low` → 횡보 고변동 구간 시나리오 배정

**C2. 레버리지 상품에 대해 어느 정도 알고 계신가요?**
`설명할 수 있다 / 들어봤고 대략 안다 / 이름만 안다 / 처음 듣는다`
→ `leverage_self_report`. **C1(실제 이해)과 C2(자기 인식)의 괴리 자체가 결과 보고서의 재료**가 된다

---

## SECTION D. 정보 출처 검증 습관 (2문항) — **스펙 신규 요구**
> → 평가 항목 **「정보 출처 검증」(15점)**의 기준선. PoC 배점 3위 항목

**D1. 투자 판단을 내릴 때 가장 크게 의존하는 정보는?** *(단일선택)*
`공시·사업보고서 / 언론 기사 / 증권사 리포트 / 커뮤니티·SNS 여론 / 차트 / 지인 추천 / 직감`
→ 커뮤니티·지인·직감 선택 시 **커뮤니티 게시물 밀도가 높은 시나리오** 배정

**D2. 투자 관련 정보를 접했을 때, 보통 어떻게 하시나요?** *(단일선택)*

| 선택지 | 태그 |
|---|---|
| 원문(공시·사업보고서)을 직접 찾아본다 | `verify_primary` |
| 다른 기사나 글로 교차 확인한다 | `verify_cross` |
| 작성자나 출처가 누구인지 확인한다 | `verify_source` |
| 특별히 확인하지 않는다 | `verify_none` |

→ **선언한 검증 습관 vs 평가 중 실제 열람 행동**을 대조한다. 결과 보고서에서 가장 강한 문장을 만들어내는 문항

---

## SECTION E. 관심 자산 및 산업 (1문항)

**E1. 관심 있는 분야를 최대 3개 골라주세요.** *(복수선택, 최대 3)*
`반도체·IT / 2차전지·에너지 / 바이오·헬스케어 / 금융 / 소비재·유통 / 엔터·콘텐츠 / 방산·중공업 / 특별히 없음`
→ **가명 자산의 섹터 프로파일**에 반영 *(실존 기업이 아닌 가상 기업으로 생성)*

---

## SECTION F. 감수 가능한 위험 수준 (1문항) — ⭐ **최우선 · 삭제 불가**
> → 평가 항목 **「위험 한도 준수」(20점)**의 기준선. **최대 배점 항목**

**F1. 이번 평가에서, 최대 얼마까지 손실이 나도 괜찮다고 생각하시나요?**

| 선택지 | `risk_limit` |
|---|---|
| 5% 이내 | 5 |
| 10% 이내 | 10 |
| 20% 이내 | 20 |
| 30% 이내 | 30 |
| 손실 폭은 신경 쓰지 않겠다 | `unbounded` |

**보조 문구 (필수 노출)**
```
이 답변은 점수를 깎는 데 쓰이지 않습니다.
평가가 끝난 뒤, 실제로 이 기준을 지키셨는지 보여드립니다.
```

> 💡 **"점수에 반영되지 않는다"고 명시**해야 솔직한 답이 나오고, 결과 보고서의 대조가 아프게 작동한다.
> 스펙의 평가 기준 *"사전에 밝힌 위험 수준과 실제 판단의 일치 여부"*가 정확히 이 문항을 가리킨다.

## 🔧 성향 분석 출력 (spec 요구 5종)

AI는 응답을 받아 다음을 생성한다. **시나리오는 사전 검수된 목록 안에서만 선택한다.**

```json
{
  "profile_summary": "레버리지 상품을 거래한 적은 없지만 위험 선호도가 높고, 커뮤니티 여론에 크게 의존하는 유형입니다.",
  "strengths": ["손실 상황에서 즉시 정리하는 결단력"],
  "weaknesses": [
    "레버리지의 변동성 잠식을 인지하지 못함 (C1 오답, C2는 '대략 안다')",
    "정보를 교차 확인하지 않음 (D2: verify_none)"
  ],
  "priority_learning": ["변동성 잠식", "정보 출처 구분"],
  "recommended_scenario_ids": ["SC-014", "SC-007"],
  "assignment_reason": "레버리지 미경험 + 커뮤니티 의존 → 커뮤니티 낙관론이 팽배한 횡보 고변동 구간",
  "scoring_baseline": {
    "risk_limit_pct": 20,
    "declared_verification": "verify_none",
    "leverage_literacy": "low"
  }
}
```

> ⚠️ `recommended_scenario_ids`는 **사전 검수된 시나리오 카탈로그의 ID**여야 한다.
> AI가 시나리오를 생성하지 않는다는 것이 스펙의 명시적 제약이다.

## 💡 결과 보고서에서 만들어질 문장

> 이 문항 설계의 최종 목적은 아래와 같은 **개인화된 지적**을 가능하게 하는 것이다.

- *"평가 전 손실 한도를 20%로 밝히셨습니다. 실제로는 4분 12초 시점에 -37%까지 갔고, 그 구간에서 판단을 바꾸지 않으셨습니다."* — 위험 한도 준수 (20점)
- *"레버리지 상품을 '대략 안다'고 답하셨지만, 기초자산이 제자리로 돌아와도 2배 상품은 제자리가 아니라는 점은 알지 못하셨습니다. 이번 평가에서 그 상황이 실제로 나왔습니다."* — 레버리지 통제 (20점)
- *"정보를 특별히 확인하지 않는다고 하셨습니다. 이번 평가에서 커뮤니티 게시물을 본 뒤 30초 이내에 방향을 바꾼 것이 6회, 공시를 열어본 것은 1회였습니다."* — 정보 출처 검증 (15점)
- *"3번째 판단이 틀린 직후 40초 만에 레버리지 자산을 UP으로 바꾸셨습니다. 이런 전환이 4회 반복됐습니다."* — 손실 이후 행동 (10점)

## 🔴 확인 필요

1. **문항 수** — 스펙 7개 항목을 10문항으로 구현했다. 온보딩 이탈률을 고려해 더 줄인다면 **F1·C1·D2는 유지 필수**(각각 20점·5점·15점 항목의 기준선).
2. **기초 개념 퀴즈(5점)의 위치** — C1을 퀴즈로 겸용할지, 평가 종료 후 별도 출제할지 미정. 겸용하면 문항 수를 줄일 수 있으나 사전 학습 효과가 생긴다.
3. **평가 시간 선택**(6/12/30/60/120분)은 성향 문항이 아니라 **시나리오 배정 직전 별도 선택 화면**으로 둔다.

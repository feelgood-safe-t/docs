# 온보딩 투자 성향 설문 — 문항 명세서 v1.0

> **확정:** 2026-09-02 미팅 — **10문항 확정.** 각 문항의 질문·선택지·세부 명세를 확립한다.
> **근거:** `spec/README.md` §PoC 기능 범위 → 사용자 성향 분석
> **용도:** ① LLM 시뮬레이션 자동 매칭의 입력 ② 과정 평가의 **채점 기준선**
> **수신:** 백엔드(문항 등록 · 응답 저장) / 프론트(온보딩 화면) / 엔진(매칭·채점)
> **분량:** 10문항 · 약 80초 · 진행률 바 표시

---

## 0. 설계 원칙

| # | 원칙 |
|---|---|
| **P1** | 모든 문항은 **시나리오 매칭** 또는 **채점 기준선** 중 하나 이상에 반드시 쓰인다. 장식용 문항 없음 |
| **P2** | 문항은 **1화면 1문항**. 스크롤 없이 선택지가 모두 보여야 한다 |
| **P3** | **정답 피드백을 주지 않는다.** C1은 지식 확인 문항이지만 온보딩에서 정오를 알려주지 않는다 *(사후 기초 개념 퀴즈의 사전 학습 방지)* |
| **P4** | 뒤로 가기 허용, 건너뛰기 불가 (전 문항 필수) |
| **P5** | 실명·계좌·실제 자산 규모를 묻지 않는다 *(스펙 비기능 조건)* |

## 0.1 스펙 7개 항목과의 매핑

| spec 요구 항목 | 문항 | 쓰임 |
|---|---|---|
| 투자 경험 | `A1` `A2` | 시나리오 난이도 |
| 위험 선호도 | `B1` | 시나리오 변동성 강도 |
| **레버리지 이해도** | `C1` `C2` | 레버리지 자산 비중 · 사후 퀴즈 난이도 |
| 손실 대응 성향 | `B2` | 시나리오 낙폭 구간 설계 |
| **정보 출처 검증 습관** | `D1` `D2` | **「정보 출처 검증」 채점 기준선** |
| 관심 자산 및 산업 | `E1` | 가명 자산의 섹터 프로파일 |
| **평가 시 감수 가능한 위험 수준** | `F1` | **「위험 한도 준수」 20점 기준선** |

> ⭐ **`F1`은 최대 배점(20점) 항목의 기준선이다. 어떤 경우에도 삭제하지 않는다.**

## 2. 문항 명세

> **표기** — `value`는 백엔드 저장값(불변), `label`은 화면 노출 문구.
> `단일`=단일선택 / `복수`=복수선택. 모든 문항 **필수**.

### A1 · 투자 경험 기간

| | |
|---|---|
| **질문** | 투자 경험이 어느 정도인가요? |
| **유형** | 단일 · 필수 |
| **필드** | `experience_years` (string enum) |
| **쓰임** | 시나리오 난이도, 튜토리얼 노출 여부 |

| value | label | 파생 태그 |
|---|---|---|
| `none` | 아직 해본 적 없어요 | `difficulty=intro` · 튜토리얼 강제 · 이벤트 밀도↓ |
| `under_1y` | 1년 미만 | `difficulty=basic` |
| `1_3y` | 1~3년 | `difficulty=standard` |
| `over_3y` | 3년 이상 | `difficulty=advanced` · 이벤트 밀도↑ |

---

### A2 · 거래 경험 상품

| | |
|---|---|
| **질문** | 다음 중 거래해 본 상품을 모두 골라주세요. |
| **유형** | 복수 · 필수 (최소 1개) |
| **필드** | `traded_products` (string[]) |
| **쓰임** | **레버리지 미경험자에게 레버리지 자산이 포함된 시나리오를 우선 배정** |

| value | label |
|---|---|
| `kr_stock` | 국내 주식 |
| `global_stock` | 해외 주식 |
| `etf` | ETF |
| `leverage` | 레버리지·인버스 ETF·ETN |
| `derivatives` | 파생상품 (선물·옵션) |
| `crypto` | 가상자산 |
| `none` | 없음 |

**규칙**
- `none` 선택 시 다른 항목과 동시 선택 불가 (배타)
- `leverage` **미선택** → `leverage_experience=false` → 제도상 이수 의무 대상과 동일 집단으로 분류

---

### B1 · 위험 선호도

| | |
|---|---|
| **질문** | "원금 손실 가능성이 없다면, 수익률이 낮아도 괜찮다" |
| **유형** | 단일 · 5점 척도 · 필수 |
| **필드** | `risk_appetite` (integer 1–5) |
| **쓰임** | 시나리오 변동성 강도 |

| value | label |
|---|---|
| `1` | 전혀 아니다 |
| `2` | 아니다 |
| `3` | 보통이다 |
| `4` | 그렇다 |
| `5` | 매우 그렇다 |

**규칙** — 값이 **낮을수록**(손실 회피 약함 = 위험 선호 높음) 고변동 시나리오를 배정한다.

---

### B2 · 손실 대응 성향

| | |
|---|---|
| **질문** | 투자한 자산이 하루 만에 -20%가 되었습니다. 첫 반응은? |
| **유형** | 단일 · 필수 |
| **필드** | `loss_reaction` (string enum) |
| **쓰임** | 시나리오 낙폭 구간 설계 · **「손실 이후 행동」(10점) 기준선** |

| value | label | 파생 태그 |
|---|---|---|
| `exit_all` | 즉시 전부 정리한다 | `panic_exit` |
| `partial` | 일부만 정리하고 지켜본다 | `balanced` |
| `hold` | 그대로 둔다 | `hold_bias` |
| `add_more` | 더 늘린다 | `chase_down` → **하락 지속 시나리오 우선 배정** |

---

### C1 · 레버리지 이해도 (지식 확인)

| | |
|---|---|
| **질문** | 다음 문장이 맞다고 생각하시나요?<br>**"기초자산이 한 달 뒤 제자리로 돌아오면, 2배 레버리지 상품도 대체로 제자리로 돌아온다."** |
| **유형** | 단일 · 필수 |
| **필드** | `leverage_quiz` (string enum) |
| **정답** | `no` (변동성 잠식) |
| **쓰임** | `leverage_literacy` 산출 · 사후 기초 개념 퀴즈 난이도 |

| value | label |
|---|---|
| `yes` | 그렇다 |
| `no` | 아니다 |
| `unknown` | 잘 모르겠다 |

> ⚠️ **P3 — 온보딩에서 정답을 알려주지 않는다.** 정오 피드백·해설 노출 금지.
> 오답(`yes`/`unknown`) → `leverage_literacy=low` → **횡보 고변동 구간** 시나리오 배정 (변동성 잠식 체감이 목적)

---

### C2 · 레버리지 자기 인식

| | |
|---|---|
| **질문** | 레버리지 상품에 대해 어느 정도 알고 계신가요? |
| **유형** | 단일 · 필수 |
| **필드** | `leverage_self_report` (string enum) |
| **쓰임** | **C1(실제 이해)과의 괴리** 자체가 결과 보고서의 재료 |

| value | label |
|---|---|
| `can_explain` | 설명할 수 있다 |
| `roughly` | 들어봤고 대략 안다 |
| `name_only` | 이름만 안다 |
| `never` | 처음 듣는다 |

**파생 지표** — `overconfidence_gap` : `C2 ∈ {can_explain, roughly}` **AND** `C1 ≠ no` → `true`
> 결과 보고서 문장으로 직결: *"'대략 안다'고 답하셨지만, 기초자산이 제자리로 돌아와도 2배 상품은 제자리가 아니라는 점은 알지 못하셨습니다."*

| | |
|---|---|
| **질문** | 투자 판단을 내릴 때 가장 크게 의존하는 정보는? |
| **유형** | 단일 · 필수 |
| **필드** | `primary_info_source` (string enum) |
| **쓰임** | 시나리오의 **커뮤니티 게시물 밀도** 결정 |

| value | label | 파생 |
|---|---|---|

| `news` | 언론 기사 | `source_tier=secondary` |

| `acquaintance` | 지인 추천 | `source_tier=crowd` → 동일 |
| `intuition` | 직감 | `source_tier=none` → 동일 |

### D2 · 정보 검증 습관 ⭐

| | |
|---|---|
| **질문** | 투자 관련 정보를 접했을 때, 보통 어떻게 하시나요? |
| **유형** | 단일 · 필수 |
| **필드** | `verification_habit` (string enum) |
| **쓰임** | **「정보 출처 검증」 채점 기준선.** 선언한 습관 vs 평가 중 실제 열람 행동을 대조 |

| value | label | 파생 태그 |
|---|---|---|
| `primary` | 원문(공시·사업보고서)을 직접 찾아본다 | `verify_primary` |
| `cross` | 다른 기사나 글로 교차 확인한다 | `verify_cross` |
| `source` | 작성자나 출처가 누구인지 확인한다 | `verify_source` |
| `none` | 특별히 확인하지 않는다 | `verify_none` |

> 결과 보고서 문장으로 직결: *"정보를 특별히 확인하지 않는다고 하셨습니다. 이번 평가에서 커뮤니티 게시물을 본 뒤 30초 이내에 방향을 바꾼 것이 6회, 공시를 열어본 것은 1회였습니다."*

### E1 · 관심 분야

| | |
|---|---|
| **질문** | 관심 있는 분야를 골라주세요. (최대 3개) |
| **유형** | 복수 · 최대 3개 · 필수 (최소 1개) |
| **필드** | `interest_sectors` (string[], maxItems 3) |
| **쓰임** | **가명 자산의 섹터 프로파일** — 실존 기업이 아닌 가상 기업으로 생성 |

| value | label |
|---|---|
| `semiconductor` | 반도체·IT |
| `battery` | 2차전지·에너지 |
| `bio` | 바이오·헬스케어 |
| `finance` | 금융 |
| `consumer` | 소비재·유통 |
| `entertainment` | 엔터·콘텐츠 |
| `defense` | 방산·중공업 |
| `none` | 특별히 없음 |

**규칙** — `none` 선택 시 다른 항목과 동시 선택 불가 (배타). `none`이면 시나리오 카탈로그의 기본 섹터를 사용한다.

### F1 · 감수 가능한 위험 수준 ⭐ 최우선

| | |
|---|---|
| **질문** | 이번 평가에서, 최대 얼마까지 손실이 나도 괜찮다고 생각하시나요? |
| **유형** | 단일 · 필수 |
| **필드** | `risk_limit_pct` (integer \| null) |
| **쓰임** | **「위험 한도 준수」 20점 — 최대 배점 항목의 유일한 기준선** |

| value | label | `risk_limit_pct` |
|---|---|---|
| `5` | 5% 이내 | 5 |
| `10` | 10% 이내 | 10 |
| `20` | 20% 이내 | 20 |
| `30` | 30% 이내 | 30 |
| `unbounded` | 손실 폭은 신경 쓰지 않겠다 | `null` |

**필수 보조 문구 (화면에 반드시 노출)**
```
이 답변은 점수를 깎는 데 쓰이지 않습니다.
평가가 끝난 뒤, 실제로 이 기준을 지키셨는지 보여드립니다.
```

> 💡 **"점수에 반영되지 않는다"고 명시해야 솔직한 답이 나오고, 결과 보고서의 대조가 작동한다.**
> 스펙의 평가 기준 *"사전에 밝힌 위험 수준과 실제 판단의 일치 여부"*가 정확히 이 문항을 가리킨다.

> 🔴 **확인 필요 — 손실 한도의 적용 단위**
> 2026-09-02 미팅에서 세션이 *"3개 문항 × 문항당 3분"* 구조로 언급됐다. 이 경우 F1의 `risk_limit_pct`가
> **(a) 세션 전체 누적 손실 기준**인지 **(b) 문항(종목)별 손실 기준**인지에 따라 채점 로직이 달라진다.
> `unbounded`는 어느 해석이든 "한도 없음"으로 처리하되, **(a)/(b) 확정 전에는 채점 규칙을 고정하지 말 것.**

## 3. 응답 JSON 스키마 (백엔드 저장 형식)

```json
{
  "profile_id": "uuid",
  "created_at": "2026-09-02T10:30:00Z",
  "answers": {
    "A1": { "field": "experience_years",      "value": "under_1y" },
    "A2": { "field": "traded_products",       "value": ["kr_stock", "etf"] },
    "B1": { "field": "risk_appetite",         "value": 4 },
    "B2": { "field": "loss_reaction",         "value": "add_more" },
    "C1": { "field": "leverage_quiz",         "value": "yes" },
    "C2": { "field": "leverage_self_report",  "value": "roughly" },
    "D1": { "field": "primary_info_source",   "value": "community" },
    "D2": { "field": "verification_habit",    "value": "none" },
    "E1": { "field": "interest_sectors",      "value": ["semiconductor", "bio"] },
    "F1": { "field": "risk_limit_pct",        "value": 20 }
  },
  "derived": {
    "difficulty": "basic",
    "leverage_experience": false,
    "leverage_literacy": "low",
    "overconfidence_gap": true,
    "source_tier": "crowd",
    "behavior_tags": ["chase_down", "verify_none"]
  },
  "scoring_baseline": {
    "risk_limit_pct": 20,
    "risk_limit_scope": "TBD",
    "declared_verification": "verify_none",
    "leverage_literacy": "low"
  }
}
```

> `derived`는 **결정적 규칙**으로 산출한다 (LLM 아님). 재현성 확보를 위해 필수.
> `scoring_baseline`은 채점 엔진이 그대로 읽는 값이다. `risk_limit_scope`는 위 🔴 확정 후 `session` 또는 `per_asset`으로 채운다.

## 4. LLM 성향 분석 출력 (스펙 요구 5종)

`derived`와 `answers`를 입력으로 LLM이 다음을 생성한다.
**시나리오는 사전 등록된 카탈로그 안에서만 선택한다.**

```json
{
  "profile_summary": "레버리지 상품을 거래한 적은 없지만 위험 선호도가 높고, 커뮤니티 여론에 크게 의존하는 유형입니다.",
  "strengths": ["관심 분야가 뚜렷해 정보 탐색의 출발점이 분명함"],
  "weaknesses": [
    "레버리지의 변동성 잠식을 인지하지 못함 (C1 오답, C2는 '대략 안다')",
    "정보를 교차 확인하지 않음 (D2: none)",
    "하락 시 추가 매수 성향 (B2: add_more)"
  ],
  "priority_learning": ["변동성 잠식", "정보 출처 구분"],
  "recommended_scenario_ids": ["SC-014", "SC-007"],
  "assignment_reason": "레버리지 미경험 + 커뮤니티 의존 → 커뮤니티 낙관론이 팽배한 횡보 고변동 구간"
}
```

> ⚠️ `recommended_scenario_ids`는 **사전 등록된 시나리오 카탈로그의 ID**여야 한다.
> AI가 시나리오를 생성하지 않는 것이 스펙의 명시적 제약이다.

## 5. 결과 보고서로 이어지는 문장

> 문항 설계의 최종 목적은 아래와 같은 **개인화된 지적**을 가능하게 하는 것이다.

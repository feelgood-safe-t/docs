# UI/UX 화면 흐름 및 와이어프레임 v0.5
### AI 레버리지 안전투자 훈련 플랫폼 「SAFE-T」

> **협업:** 기획·UX 담당 ↔ 프론트엔드 담당
> **전제:** 모바일 웹 우선(Mobile-first), 데스크톱 반응형. 설치·로그인 마찰 최소화
> **심사 관점:** 심사위원은 **배포 URL에 처음 들어와 5분 안에 가치를 이해**해야 한다. 온보딩이 곧 심사 시연이다.

---

## 0. 설계 원칙 4가지

| # | 원칙 | 구현 함의 |
|---|---|---|
| **U1** | **첫 화면에서 3클릭 안에 시장이 열려야 한다** | 회원가입 없이 익명 세션 시작. '데모로 바로 체험' 진입점 필수 |
| **U2** | **수익률은 주인공이 아니다** | 수익률은 작게, **과정 점수와 리스크 게이지를 크게**. 랭킹 보드 없음 |
| **U3** | **위험은 숫자가 아니라 감각으로 전달한다** | 레버리지 보유 시 화면 상단에 상시 경고 밴드, 낙폭에 따른 색/모션 반응 |
| **U4** | **모든 생성 콘텐츠에 라벨** | 뉴스·커뮤니티 카드에 `시뮬레이션 생성` 배지 상시 노출 (기획서 7번 안전장치와 연결) |

## 1. 전체 화면 흐름

```
 [L] 랜딩
  │  "실전에서 잃기 전에, 먼저 잃어보세요"
  │  ├─▶ [바로 체험하기] ─── 익명 세션 즉시 시작 (심사위원 동선)
  │  └─▶ [소개 보기]
  ▼
 [O] 온보딩 성향 진단 (12문항 · 90초)
  │  진행률 바 · 카드형 1문항 1화면 · 스와이프
  ▼
 [S] 시나리오 배정
  │  ┌ AI 추천 시나리오 3종 카드
  │  └ [직접 만들기] ─▶ [S2] 자연어 입력
  │                      "금리 인상 지속, 외국인 순매도, 실적 쇼크"
  │                      → AI가 파라미터로 변환 → 미리보기
  ▼
 [B] 브리핑 (세션 시작 전)
  │  이번 시장의 배경 / 보유 자산 / 학습 목표 / 손절선 사전 선언 ★
  ▼
 [T] 트레이딩 룸  ◀── 서비스의 심장
  │  차트 · 호가 · 주문 · 뉴스피드 · 포트폴리오 · 리스크 게이지
  │  시간 배속 제어 (일봉 자동 진행 / 일시정지)
  │  ├─▶ [E] 이벤트 인터럽트 (급락·공시·서킷브레이커 모달)
  │  └─▶ [A] AI 코치 사이드패널 (질문 시에만 응답, 답을 주지 않고 되묻기)
  ▼
 [R] 결과 디브리핑
  │  1) 무슨 일이 있었나 (시장 해설 + 내 매매 시점 오버레이)
  │  2) 당신은 이렇게 했습니다 (과정 지표 6종 레이더)
  │  3) 선언 vs 실행 대조 ★ 가장 강한 화면
  │  4) 이번에 배운 개념 카드
  │  5) 다음 추천 시나리오
  ▼
 [C] SAFE-T 이수 리포트
     누적 세션 기반 역량 프로파일 + SAFE-T 이수 리포트(PDF)
     ※ "공인 자격 아님 · 학습 이수 증명" 명시
```

## 3. 비주얼 디렉션 (초안)

| 요소 | 방향 |
|---|---|
| 톤 | **진지한 다크 UI** — 게임이 아니라 훈련. 증권 HTS의 신뢰감 + 교육 도구의 명료함 |
| 컬러 | 배경 딥네이비·차콜. **상승 빨강 · 하락 파랑 (국내 증권 관행)** — 심사위원이 국내 금융권이므로 글로벌 관행(상승 녹색) 아님. 강조색 1종(시안 또는 앰버) |
| 타이포 | 숫자는 tabular numerals 고정폭 필수 (가격 흔들림 방지) |
| 모션 | 급락 시 화면 미세 진동/색 번짐 — **과하면 게임처럼 보이므로 절제** |
| 경고 표현 | 레버리지 보유 시 상단 밴드 상시 노출, 시간 경과에 따라 강조도 상승 |

## 4. 🔴 프론트엔드 담당과 확정할 사항
1. 화면 우선순위 — MVP에 **반드시 들어갈 화면**은? *(제안: L → O(축약) → S/S2 → T → R 5개)*
2. 차트 라이브러리 및 데이터 갱신 방식
3. 모바일 트레이딩 룸 레이아웃 (탭 vs 단일 스크롤)
4. 디자인 툴 — Figma 사용 여부 및 공유 방식
5. 심사위원용 **데모 계정/샘플 시나리오 프리셋** 필요 여부 *(기능명세서 5번 'MVP 검증 방법'에 필수 기재 항목)*
6. 컴포넌트 라이브러리 (shadcn/ui 등) 채택 여부

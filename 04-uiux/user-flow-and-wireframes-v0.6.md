# UI/UX 화면 흐름 및 와이어프레임 v0.6
### AI 레버리지 안전투자 훈련 플랫폼 「Safe-T」

> **기준:** `spec/README.md` — 캐주얼 판단 모드 (PoC 범위)
> **협업:** 기획·UX 담당 ↔ 프론트엔드 담당
> **전제:** 모바일 웹 우선(Mobile-first), 데스크톱 반응형. 설치·로그인 마찰 최소화
> **심사 관점:** 심사위원은 **배포 URL에 처음 들어와 짧은 시간 안에 가치를 이해**해야 한다. 온보딩이 곧 심사 시연이다.
>
> v0.6 = 스펙 반영본. 실전형 모의투자(매수·매도·비중·손절) 화면은 전부 제거하고 UP/DOWN 판단 모드로 재작성.
> **2026-09-01 갱신** — 실제 구현 시안(`04-uiux/assets/mockup-evaluation-screen.png`)을 반영. §2 `[T]` 화면과 §3 비주얼 디렉션을 시안 기준으로 재작성하고, §5에 **스펙 대비 누락 요소 체크리스트**를 추가했다.

## 0. 설계 원칙 5가지

| # | 원칙 | 구현 함의 |
|---|---|---|
| **U1** | **3클릭 안에 평가가 시작돼야 한다** | 회원가입 없이 익명 세션. 심사위원용 **프리셋 프로파일 + 바로 시작** 경로 필수 |
| **U2** | **수익률은 주인공이 아니다** | 적중률·예상 수익률은 결과 화면에서만, 작게. **과정 점수를 크게.** 랭킹 보드 없음 |
| **U3** | **위험은 숫자가 아니라 감각으로 전달한다** | 레버리지 자산을 UP으로 둔 동안 상단 경고 밴드 상시 노출, 노출 시간 누적 표시 |
| **U4** | **모든 생성 콘텐츠에 라벨** | 뉴스·공시·커뮤니티 카드에 `AI 생성 시뮬레이션 콘텐츠` 배지 상시 노출 |
| **U5** | **정보 출처가 시각적으로 구분돼야 한다** | 공시 / 기사 / 커뮤니티를 **색·아이콘·라벨로 명확히 분리**하고 **열람 행동을 로깅**한다 → 정보 출처 검증(15점) 채점 근거 |

## 1. 전체 화면 흐름

```
 [L] 랜딩
  │  "실제 돈을 잃기 전에, 먼저 겪어보세요"
  │  ├─▶ [바로 체험하기] ── 익명 세션 즉시 시작 (심사위원 동선)
  │  └─▶ [소개 보기]
  ▼
 [O] 성향 설문 (10문항 · 약 80초)
  │  카드형 1문항 1화면 · 진행률 바
  │  마지막 문항 = 감수 가능한 위험 수준 ★ 채점 기준선
  ▼
 [P] AI 성향 분석 결과
  │  성향 요약 / 강점 / 취약점 / 우선 학습 항목
  ▼
 [S] 시나리오 배정 + 평가 시간 선택
  │  AI가 고른 시나리오 + 배정 이유
  │  평가 시간: 6 / 12 / 30 / 60 / 120분
  ▼
 [B] 브리핑
  │  등장 자산 3종 / 밝힌 위험 한도 재확인 / 조작 방법 안내
  ▼
 [T] 평가 화면 ◀── 서비스의 심장
  │  자산 3개 · 차트 · 수급 · 참고지표 · 정보 피드 · UP/DOWN
  │  서버 시간 60배속 진행 (정지 불가)
  │  ├─▶ [X] 이탈 → 재접속 시 [T2] 이어하기
  │  └─▶ [E] 이벤트 배너 (급락·공시·서킷브레이커)
  ▼
 [Q] 기초 개념 퀴즈 (3~5문항 · 5점)
  ▼
 [R] 결과 보고서
  │  1) 총점과 항목별 점수
  │  2) 밝힌 위험 한도 vs 실제 ★ 가장 강한 화면
  │  3) 판단 변경 타임라인 + 확인한 정보 출처
  │  4) 가장 적절했던 판단 / 가장 위험했던 판단
  │  5) 반복된 행동 패턴 · 개선 습관 · 추천 후속 학습
  ▼
 [C] INVEST PASS 발급 (70점 이상)
     인증 코드 · 평가 시간 · 시나리오 유형 · 최종 점수 · 발급일 · 검증 페이지
     ※ "공인 금융 자격 아님" 고정 안내문
```

```
> ✅ **확신도(`★☆☆`)와 판단 근거 태그는 입력에서 제외한다.** 판단은 **UP / DOWN 단일 액션**으로 끝난다.
> 근거는 §5 하단 「입력 축소 결정」 참조.

```

**시안이 잘 해결한 것**

| 항목 | 평가 |
|---|---|
| **자산 3개 표시** | 스와이프 캐러셀 + 페이지 도트 + 안내 문구. 열린 질문이었던 *탭 vs 스택 vs 스와이프*가 **스와이프로 확정**됨. 모바일에서 한 자산에 집중시키는 효과도 있다 |
| **정보 출처 분리** | 뉴스 / 공시 / 커뮤니티 **탭 전환**. 탭 전환이 곧 **명시적 열람 행동**이므로 정보 출처 검증(15점) 로깅이 자연스럽게 성립한다 |
| **수급 데이터** | 개인·외국인·기관 당일 흐름 노출. 스펙 요구 충족 |
| **위험 정보 전면화** | `보통위험` 등급과 `레버리지 1.0x` 배수를 종목명 옆에 배지로. 자산을 넘길 때마다 위험도가 먼저 읽힌다 |
| **진입 장벽** | UP/DOWN 두 버튼과 *"오를 것 같아요!"* 카피. 투자 경험이 없어도 무엇을 하는 화면인지 즉시 이해된다 |
| **가명화** | `테크노바이오 (TNB)`, `바이오헤럴드` — 종목·티커·언론사까지 가상. 스펙 원칙 준수 |

**필수 동작**
- 판단은 **UP / DOWN 한 번의 탭으로 완료.** 추가 입력을 요구하지 않는다
- 판단은 **언제든 변경 가능**. 변경하지 않으면 직전 판단이 유지된다
- 정보 탭 전환·카드 열람 이벤트를 **타임스탬프와 함께 로깅** — 정보 출처 검증 채점과 **판단 근거 추정**의 유일한 근거
- 판단 시각·직전 열람 정보·직전 판단을 함께 기록 (스펙 판단 로그 항목)
- 배속 제어·일시정지 **없음** (서버 시간 기준 진행)

## 3. 비주얼 디렉션 — 구현 시안 기준으로 재작성

> v0.5까지는 *"진지한 다크 UI"*를 전제했으나, 실제 시안은 **밝은 크림 배경 + 픽셀 레트로** 방향이다.
> 스펙의 *"복잡한 주문 없이 누구나 게임처럼 참여할 수 있어, 대중 대상 위험투자 교육 모드로도 독립적 가치가 있다"*
> 는 서술과 부합하므로 **시안 방향을 채택**하고, 아래 표를 그 기준으로 다시 쓴다.

| 요소 | 방향 |
|---|---|
| 톤 | **밝은 크림 섀시 + 어두운 데이터 패널.** 바깥은 친근한 레트로 게임기, 안쪽 차트·지표 영역은 증권 단말의 밀도 — **접근성과 신뢰감을 층으로 분리** |
| 타이포 | 로고·UP/DOWN 등 조작 요소는 **픽셀 폰트**, 수치는 **tabular numerals 고정폭** (가격 흔들림 방지). 두 서체의 역할을 섞지 않는다 |
| 컬러 | 크림 `#F0E6D2` 계열 섀시 / 딥그린 `#0E2A1A` 계열 데이터 패널 / 강조 그린. **등락은 국내 관행(상승 빨강 · 하락 파랑)** — 아래 확정안 참조 |
| **출처 구분** | 시안은 **탭 전환** 방식. 탭에 색·아이콘 위계를 더할 것 — 공시 = 중립 블루(1차 출처) / 기사 = 뉴트럴 그레이 / 커뮤니티 = 앰버(주의). **정보 신뢰도의 위계를 색으로 학습시킨다** |
| 모션 | 급락 시 화면 미세 진동 등은 **절제.** 레트로 톤에서는 과한 모션이 도박성 연출로 읽히기 쉽다 |
| 경고 표현 | 위험 등급·레버리지 배수 배지는 시안대로 유지 + **레버리지 자산을 UP으로 유지하는 동안 상단 경고 밴드와 누적 노출 시간** 추가 (U3) |

### ✅ 확정 — 등락 색상과 UP/DOWN 버튼 구분 방식

시안은 상승 초록/하락 빨강(글로벌 관행)이었으나, 심사위원단이 금융위·금융보안원·은행·증권사로 **전원 국내 금융권**이므로 **캔들은 국내 관행을 따른다.** 대신 UP/DOWN 버튼은 색 의존도를 낮춘다.

**① 캔들·수치 — 국내 증권 관행**

| 방향 | 색 |
|---|---|
| 상승 | **빨강** |
| 하락 | **파랑** |
| 보합 | 뉴트럴 그레이 |

→ 현재가·전일대비·등락률·고가/저가·수급 수치도 동일 체계를 따른다.

**② UP/DOWN 버튼 — 형태와 텍스트가 1차 구분**

| 우선순위 | 구분 요소 |
|---|---|
| **1차** | **방향 화살표** `▲▲▲` / `▼▼▼` — 크고 굵게, 버튼의 시각적 주인공 |
| **2차** | **텍스트** `UP` / `DOWN` + 보조 카피 *"오를 것 같아요!"* / *"내릴 것 같아요!"* |
| **3차** | 색 — **캔들과 같은 체계**를 채도를 낮춰 옅게 적용 (UP = 저채도 레드 / DOWN = 저채도 블루) |
| 선택 상태 | **채움(fill) vs 외곽선(outline)** + 테두리 강조. 색만으로 선택 여부를 표현하지 않는다 |

**왜 이렇게 하는가**
- 시안의 초록 UP 버튼을 그대로 두면 **버튼의 초록(상승)과 캔들의 빨강(상승)이 정면 충돌**한다. 버튼 색을 캔들과 같은 체계로 맞추면 화면 전체가 하나의 색 언어를 갖는다
- 다만 **빨강 버튼은 '경고·위험'으로 읽힐 수 있으므로 채도를 낮추고**, 판단은 화살표와 텍스트로 읽히게 한다
- 색 외 구분 요소(화살표·텍스트·채움 상태)가 있어 **색각 이상 접근성**도 확보된다

**③ 출처 구분색과의 충돌 방지**
정보 출처 색 위계(공시 = 블루)와 하락 파랑이 겹칠 수 있다. **출처 색은 카드 좌측 보더와 탭 인디케이터에만**, 등락 색은 **수치와 캔들에만** 적용해 영역을 분리한다.

## 6. ✅ 입력 축소 결정 — 확신도·판단 근거 태그 제거

> 결정일 2026-09-01 · **UI/UX 범위의 결정.** 채점 배점 처리는 팀장 결정 안건으로 이관 (`05-meetings` D7·D8)

### 무엇을 뺐는가

| 제거 | 스펙 원문 | 제거 근거 |
|---|---|---|
| **확신도** (낮음·보통·높음) | *"분석 정확도를 높이기 위해 선택 시 다음 보조정보를 받을 수 있다"* | **실제 주식 매매에 존재하지 않는 입력**이다. 실전에 없는 조작을 학습시키면 학습 전이가 떨어지고, 60배속 진행 중 추가 탭은 순수한 마찰이다 |
| **판단 근거 태그** (가격·수급·공시·뉴스·커뮤니티·거시지표·직감) | 동일 | 매 판단마다 태그를 고르게 하는 것은 **UX상 부자연스럽다.** 더 중요한 것은 — 스펙이 이미 AI 역할로 *"당시 노출된 정보를 기반으로 **판단 이유 추정**"*을 정의하고 있어 **태그 입력과 기능이 중복**된다 |

### 대신 무엇으로 측정하는가 — 행동 기반 추정

판단 로그에는 이미 다음이 기록된다.

```
선택 방향 · 선택 시각 · 당시 시장 시점 · 당시 가격과 변동성
· 열람한 뉴스와 출처 · 직전 판단
```

여기서 **"무엇을 보고 그렇게 판단했는가"를 역추정**할 수 있다.

| 관찰 신호 | 해석 |
|---|---|
| 판단 직전 N초 이내 열람한 **정보 출처 유형** | 공시를 보고 판단했는가, 커뮤니티를 보고 판단했는가 |
| 열람 → 판단까지의 **간격** | 즉흥 반응인가, 숙고인가 |
| 열람한 정보의 **방향성과 판단 방향의 정합** | 악재를 읽고 UP을 눌렀다면 근거와 판단이 어긋난 것 |
| **아무것도 열람하지 않은 채** 내린 판단의 비율 | 근거 없는 판단 |
| 동일 정보 노출 상황에서의 **판단 반복성** | 일관성 |

> ⚠️ **재현성 주의.** 이 추정을 그대로 점수화하면 *"동일 판단 기록 → 동일 점수"*라는 스펙 필수 조건과 충돌할 수 있다.
> **점수는 결정적 규칙으로 산출**하고(예: *판단 직전 60초 내 열람 출처 유형 × 판단 방향의 정합률*),
> **AI는 그 규칙 결과를 자연어로 설명**하는 역할만 맡는 구조를 권한다. 팀장 확인 요청 Q1과 직접 연결된다.

### 부수 효과

- 판단이 **한 번의 탭**으로 끝나 진입 장벽이 더 낮아진다 (스펙의 *"게임처럼 참여"* 취지에 부합)
- 사용자가 **자기 근거를 스스로 신고하지 않으므로** 자기보고 편향이 사라진다. 실제 행동만 남는다
- 결과 보고서의 지적이 더 강해진다 — *"근거를 이렇게 골랐다고 하셨죠"*가 아니라 *"공시를 열어보지 않은 채 내린 판단이 9건 중 7건이었습니다"*

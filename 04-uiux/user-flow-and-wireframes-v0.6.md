# UI/UX 화면 흐름 및 와이어프레임 v0.6
### AI 레버리지 안전투자 훈련 플랫폼 「Safe-T」

> ## ⏸️ 역할 전환 (2026-09-03)
>
> **UI 설계와 구현은 프론트엔드 담당이 전담한다.**
> 이 문서는 더 이상 *결정을 제안하는 설계안*이 아니라, **구현 결과를 문서화하기 위한 참고 자료**다.
>
> | | |
> |---|---|
> | **앞으로의 용도** | 프론트엔드 구현이 확정되면 그 결과를 **기능명세서 2번(주요 기능 목록)·3번(사용자 이용 흐름)**으로 옮겨 쓰기 위한 초안 |
> | **하지 않는 것** | 화면 구조·색상·컴포넌트 결정 제안. 아래 §4의 "확정할 사항"도 프론트 담당의 판단 사항이다 |
> | **유지하는 이유** | 스펙 대비 **규정 준수 요소**(§5 M1 `AI 생성 시뮬레이션 콘텐츠` 라벨)와 채점에 필요한 **로깅 요건**(§0 U5)은 기획·제출 서류와 직결되므로 기록을 남긴다 |
>
> ⚠️ 아래 와이어프레임은 폐기된 자유 이동 캐러셀 구조의 역사적 참고다. 현재 계약은
> **단일 자산 문항 3개를 문항당 3분씩 순차 진행하고 문항마다 UP/DOWN을 수시로 제출**하는
> 구조다. 현재 기능·API 판단에는 [`spec/README.md`](../spec/README.md)를 사용한다.

## 0. 설계 원칙 6가지

| # | 원칙 | 구현 함의 |
|---|---|---|
| **U1** | **3클릭 안에 평가가 시작돼야 한다** | 회원가입 없이 익명 세션. 심사위원용 **프리셋 프로파일 + 바로 시작** 경로 필수 |
| **U6** | **평가 중에는 점수를 보여주지 않는다** | 중간 점수가 보이면 점수 최적화 행동이 나온다. 결과는 **전 과정 종료 후 일괄 공개** |
| **U2** | **수익률·적중률을 평가하지 않는다** | 응답 후 가격은 판단 효용을 설명하는 문맥일 뿐 계산·표시·채점하지 않음 |
| **U3** | **위험 신호를 관찰하게 한다** | 캔들·거래량·시나리오 설명·뉴스를 통해 고변동 상황의 판단 근거를 제공 |
| **U4** | **모든 생성 콘텐츠에 라벨** | 뉴스·공시·커뮤니티 카드에 `AI 생성 시뮬레이션 콘텐츠` 배지 상시 노출 |
| **U5** | **정보 출처가 시각적으로 구분돼야 한다** | 공시 / 기사 / 커뮤니티를 **색·아이콘·라벨로 명확히 분리**하고 **열람 행동을 로깅**한다 → 정보 출처 검증(15점) 채점 근거 |

## 1. 전체 화면 흐름

```
 [L] 랜딩
  │  "실제 돈을 잃기 전에, 먼저 겪어보세요"
  │  ├─▶ [바로 체험하기] ── 익명 세션 즉시 시작 (심사위원 동선)
  │  └─▶ [소개 보기]
  ▼
 [O] 성향 설문 (10문항 · 약 80초)
  │  카드형 1문항 1화면 · 진행률 바
  │  마지막 문항 = 감수 가능한 위험 수준 ★ 채점 기준선
  ▼
 [P] AI 성향 분석 결과
  │  성향 요약 / 강점 / 취약점 / 우선 학습 항목
  ▼
 [S] 시나리오 배정 + 평가 시간 선택
  │  AI가 고른 시나리오 + 배정 이유
  │  평가 시간: 6 / 12 / 30 / 60 / 120분
  ▼
 [B] 브리핑
  │  등장 자산 3종 / 밝힌 위험 한도 재확인 / 조작 방법 안내
  ▼
 [T] 평가 화면 ◀── 서비스의 심장
  │  자산 3개 · 차트 · 수급 · 참고지표 · 정보 피드
  │  UP/DOWN 탭 → 근거 시트(태그 + 직접 입력) → 판단 확정
  │  서버 시간 60배속 진행 (정지 불가) · ⏹ 조기 종료 가능
  │  ※ 평가 중 점수·결과 노출 없음
  │  ├─▶ [X] 이탈 → 재접속 시 [T2] 이어하기 🔴 저장 방식 확정 필요
  │  └─▶ [E] 이벤트 배너 (급락·공시·서킷브레이커)
  ▼
 [R] 결과 보고서
  │  1) 총점과 항목별 점수
  │  2) 최초 성향 설문과 실제 판단의 정합성
  │  3) 세 문항의 전체 판단 타임라인 + 확인한 정보 출처
  │  4) 가장 적절했던 판단 / 가장 위험했던 판단
  │  5) 반복된 행동 패턴 · 개선 습관 · 추천 후속 학습
  ▼
 [C] INVEST PASS 발급 (70점 이상)
     인증 코드 · 평가 시간 · 시나리오 유형 · 최종 점수 · 발급일 · 검증 페이지
     ※ "공인 금융 자격 아님" 고정 안내문
```

| 항목 | 평가 |
|---|---|
| **자산 3개 표시** | 스와이프 캐러셀 + 페이지 도트 + 안내 문구. 열린 질문이었던 *탭 vs 스택 vs 스와이프*가 **스와이프로 확정**됨. 모바일에서 한 자산에 집중시키는 효과도 있다 |

| **위험 정보 전면화** | `보통위험` 등급과 `레버리지 1.0x` 배수를 종목명 옆에 배지로. 자산을 넘길 때마다 위험도가 먼저 읽힌다 |
| **진입 장벽** | UP/DOWN 두 버튼과 *"오를 것 같아요!"* 카피. 투자 경험이 없어도 무엇을 하는 화면인지 즉시 이해된다 |
| **가명화** | `테크노바이오 (TNB)`, `바이오헤럴드` — 종목·티커·언론사까지 가상. 스펙 원칙 준수 |

**필수 동작**
- **판단 흐름:** UP/DOWN 탭 → **근거 시트** → `판단 확정`. 근거 입력 없이는 판단이 확정되지 않는다
- 각 문항에는 UP/DOWN을 **최소 한 번** 제출하고, 시장이 진행되는 동안 같은 방향의 재확인이나
  다른 방향의 후속 판단을 수시로 추가할 수 있다. 과거 판단은 수정·삭제하지 않는다
- **각 문항마다 판단 이벤트 하나 이상이 필요**하다. 미완료 시 불이익 → 미응답 문항은 화면에 명확히 표시
- **조기 종료** 가능 — 남은 시간이 있어도 평가를 끝낼 수 있다
- **평가 중 점수·결과를 노출하지 않는다.** 전 과정 종료 후 일괄 공개
- 정보 탭 전환·카드 열람 이벤트를 **타임스탬프와 함께 로깅** — 정보 출처 검증 채점과 **판단 근거 추정**의 유일한 근거
- 모든 판단 시각·각 판단 당시 이용 가능했던 정보·실제 상세 열람을 함께 기록
- 배속 제어·일시정지 **없음** (서버 시간 기준 진행)

## 3. 비주얼 디렉션 — 구현 시안 기준으로 재작성

> v0.5까지는 *"진지한 다크 UI"*를 전제했으나, 실제 시안은 **밝은 크림 배경 + 픽셀 레트로** 방향이다.
> 스펙의 *"복잡한 주문 없이 누구나 게임처럼 참여할 수 있어, 대중 대상 위험투자 교육 모드로도 독립적 가치가 있다"*
> 는 서술과 부합하므로 **시안 방향을 채택**하고, 아래 표를 그 기준으로 다시 쓴다.

| 요소 | 방향 |
|---|---|
| 톤 | **밝은 크림 섀시 + 어두운 데이터 패널.** 바깥은 친근한 레트로 게임기, 안쪽 차트·지표 영역은 증권 단말의 밀도 — **접근성과 신뢰감을 층으로 분리** |
| 타이포 | 로고·UP/DOWN 등 조작 요소는 **픽셀 폰트**, 수치는 **tabular numerals 고정폭** (가격 흔들림 방지). 두 서체의 역할을 섞지 않는다 |
| 컬러 | 크림 `#F0E6D2` 계열 섀시 / 딥그린 `#0E2A1A` 계열 데이터 패널 / 강조 그린. **등락은 국내 관행(상승 빨강 · 하락 파랑)** — 아래 확정안 참조 |
| **출처 구분** | 시안은 **탭 전환** 방식. 탭에 색·아이콘 위계를 더할 것 — 공시 = 중립 블루(1차 출처) / 기사 = 뉴트럴 그레이 / 커뮤니티 = 앰버(주의). **정보 신뢰도의 위계를 색으로 학습시킨다** |
| 모션 | 급락 시 화면 미세 진동 등은 **절제.** 레트로 톤에서는 과한 모션이 도박성 연출로 읽히기 쉽다 |
| 경고 표현 | 위험 등급·레버리지 배수 배지는 시안대로 유지 + **레버리지 자산을 UP으로 유지하는 동안 상단 경고 밴드와 누적 노출 시간** 추가 (U3) |

### ✅ 확정 — 등락 색상과 UP/DOWN 버튼 구분 방식

시안은 상승 초록/하락 빨강(글로벌 관행)이었으나, 심사위원단이 금융위·금융보안원·은행·증권사로 **전원 국내 금융권**이므로 **캔들은 국내 관행을 따른다.** 대신 UP/DOWN 버튼은 색 의존도를 낮춘다.

**① 캔들·수치 — 국내 증권 관행**

| 방향 | 색 |
|---|---|
| 상승 | **빨강** |
| 하락 | **파랑** |
| 보합 | 뉴트럴 그레이 |

→ 현재가·전일대비·등락률·고가/저가·수급 수치도 동일 체계를 따른다.

**② UP/DOWN 버튼 — 형태와 텍스트가 1차 구분**

| 우선순위 | 구분 요소 |
|---|---|
| **1차** | **방향 화살표** `▲▲▲` / `▼▼▼` — 크고 굵게, 버튼의 시각적 주인공 |
| **2차** | **텍스트** `UP` / `DOWN` + 보조 카피 *"오를 것 같아요!"* / *"내릴 것 같아요!"* |
| **3차** | 색 — **캔들과 같은 체계**를 채도를 낮춰 옅게 적용 (UP = 저채도 레드 / DOWN = 저채도 블루) |
| 선택 상태 | **채움(fill) vs 외곽선(outline)** + 테두리 강조. 색만으로 선택 여부를 표현하지 않는다 |

**왜 이렇게 하는가**
- 시안의 초록 UP 버튼을 그대로 두면 **버튼의 초록(상승)과 캔들의 빨강(상승)이 정면 충돌**한다. 버튼 색을 캔들과 같은 체계로 맞추면 화면 전체가 하나의 색 언어를 갖는다
- 다만 **빨강 버튼은 '경고·위험'으로 읽힐 수 있으므로 채도를 낮추고**, 판단은 화살표와 텍스트로 읽히게 한다
- 색 외 구분 요소(화살표·텍스트·채움 상태)가 있어 **색각 이상 접근성**도 확보된다

**③ 출처 구분색과의 충돌 방지**
정보 출처 색 위계(공시 = 블루)와 하락 파랑이 겹칠 수 있다. **출처 색은 카드 좌측 보더와 탭 인디케이터에만**, 등락 색은 **수치와 캔들에만** 적용해 영역을 분리한다.

| **M5** | **레버리지 노출 경고 밴드** | 본 문서 U3 | 🟡 배지는 있으나 **UP 유지 중 누적 노출 시간**이 없다. 「레버리지 통제」 20점의 체감 근거 |
| **M6** | **정규화 가격 표기 정합** | 스펙: *"절대 가격"을 가명화 대상에 포함*, 정규화 공식 명시 | 🟡 차트 Y축은 96~112 정규화 스케일인데 현재가는 `105,500`으로 절대가처럼 읽힌다. **표기 기준 통일 필요** |

> **M1·M2·M4는 구현 전에 반드시 반영해야 한다.** 각각 규정 준수, 5점 채점, 조작 가능성에 직결된다.

## 6. ✅ 판단 입력 확정 (2026-09-02 미팅)

### 결정

| 입력 | 스펙 원안 | **확정** |
|---|---|---|
| **판단 근거** | *(Optional)* 태그 선택 | ⬆️ **필수** — 태그 선택 **+ 직접 입력 필드 추가** |
| **확신도** | *(Optional)* 낮음·보통·높음 | ⏸️ **미포함** — 미팅에서 언급되지 않음. 제거 상태 유지, 배점 처리는 D4 |

> **근거 입력은 오히려 무게가 올라갔다.** 스펙에서는 선택 항목이었으나, 팀은 이를 **필수**로 격상하고
> 태그만으로 표현되지 않는 판단을 담기 위해 **직접 입력**까지 추가했다.
> Safe-T의 핵심이 *"무엇을 보고 그렇게 판단했는가"*이므로 자연스러운 강화다.

### 판단 흐름

```
UP 또는 DOWN 탭
   ↓
근거 시트 (바텀 시트)
   · 태그 다중 선택 — 가격 / 수급 / 공시 / 뉴스 / 커뮤니티 / 거시지표 / 직감
   · 직접 입력 (자유 텍스트, 선택)
   ↓
[판단 확정]
```

**설계 규칙**
- **태그 1개 이상 또는 직접 입력 중 하나**면 확정 가능 (백엔드 `reasonTags | reasonText` any-of). 둘 다 비면 `422 DECISION_REASON_REQUIRED`
- 시트는 **바텀 시트**로 올라와 차트를 가리지 않는다 (근거를 떠올리며 차트를 볼 수 있어야 한다)
- 60배속 진행 중이므로 **시트 개폐는 3초 이내**에 끝날 수 있어야 한다. 태그는 스크롤 없이 한 화면에
- 🔴 **구현 확인** — 판단을 **변경**할 때도 근거를 다시 입력해야 하는가? *(제안: 필수. 변경 사유를 남기지 않으면 「판단의 일관성」 채점 근거가 사라진다)*

### 자기신고 + 행동 로그를 함께 쓴다

근거 입력이 필수가 되면서 **두 종류의 근거가 모두 확보된다.**

| 출처 | 성격 | 채점 활용 |
|---|---|---|
| **자기신고 근거** (태그 + 직접 입력) | 사용자가 *생각하는* 판단 이유 | 「판단 근거의 구체성」(5점) 직접 측정 |
| **행동 로그** (열람 출처·시각·간격) | 사용자가 *실제로 본* 정보 | 「정보 출처 검증」(15점) |

**두 값의 대조가 가장 강한 진단을 만든다.**
> *"근거로 '공시'를 선택하셨지만, 그 판단 직전 3분 동안 공시 탭을 한 번도 열지 않으셨습니다. 실제로 보신 것은 커뮤니티 게시물 4건이었습니다."*

이는 자기보고 편향을 제거하는 것이 아니라, **편향 자체를 측정 대상으로 삼는** 접근이다.

## 7. 세션 구조 — 🔴 확정 대기

미팅 노트의 두 서술이 충돌한다. **확정 전까지 화면 전환 구조를 고정하지 않는다.**

| 출처 | 서술 |
|---|---|
| 회의 내용 | *"총 3개 문항, **문항당 3분** 제한"* → 합계 9분 |
| Q3 답변 | *"심사위원은 **6분 동안** 3개 종목 화면을 자유롭게 이동하며 판단"* |

| 안 | 화면 구조 | UI 영향 |
|---|---|---|
| **가** | 종목 3개 **순차 제시**, 각 3분 | 캐러셀 대신 **단계 진행형**. 이전 종목 복귀 불가 |
| **나** | 종목 3개 **동시 제시**, 전체 6분 자유 이동 | **현재 캐러셀 구조 그대로** |
| **다** | 기본 가, 심사위원 데모만 나 | 두 모드 모두 구현 필요 |

> 현재 와이어프레임은 **나(자유 이동 캐러셀)** 기준으로 그려져 있다. 시안도 동일하다.
> **가**로 확정되면 캐러셀·판단 요약 바·스와이프 안내를 전부 다시 설계해야 한다. → **9/6 미팅 우선 안건**

## 8. 결과 공개 시점 및 저장 (2026-09-02 확정)

**공개 시점 — 전 과정 종료 후 일괄**
- 평가 중 **점수·적중률·수익률을 일절 노출하지 않는다**
- 종료(시간 만료 또는 조기 종료) → 결과 보고서 → `INVEST PASS`
- 💡 교육적으로도 옳다. 중간 점수가 보이면 **점수를 최적화하는 행동**이 나오고, 그것은 실제 투자 상황이 아니다

**저장 — 로그인 없이 브라우저 로컬 스토리지, 일회성 사이클**

| 대상 | 저장 위치 | 비고 |
|---|---|---|
| 평가 결과·`INVEST PASS` | **브라우저 로컬 스토리지** | 로그인 불필요 |
| 평가 진행 상태 | 🔴 **확인 필요** | 스펙 필수 조건은 *"서버 저장 + 재접속 이어하기"* |

> 🔴 **두 가지를 9/6에 확정해야 한다.**
> **(a) 이어하기** — 스펙은 *"평가 진행 상태는 서버에 저장되어 재접속 후 이어갈 수 있어야 한다"*를 **필수 비기능 조건**으로 둔다. 로컬 일회성 사이클이면 이 요구가 완화된 것인지 확인이 필요하다. *(제안: 진행 상태는 서버, 결과는 로컬로 분리)*
> **(b) 검증 페이지의 의미** — 결과가 로컬에만 있으면 **제3자가 인증 코드로 조회할 수 없다.** `INVEST PASS`의 "검증 페이지 주소"가 사실상 **본인 확인용**이 된다. 기획서 서술을 그에 맞춰 톤다운했다

**심사위원 관점 주의**
> 로컬 스토리지 기반이면 심사위원이 **다른 브라우저·기기로 접속하면 결과가 보이지 않는다.**
> 기능명세서 5번(MVP 검증 방법)에 *"동일 브라우저에서 확인"* 제약을 반드시 명시해야 한다.

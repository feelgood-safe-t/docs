## 🔴 9/6(토) 미팅 안건

### C1 · 세션 구조 확정 — 두 서술이 충돌한다

| 출처 | 서술 |
|---|---|
| 미팅 노트 (회의 내용) | *"테스트는 총 3개 문항으로 구성되며, **문항당 3분**의 제한 시간"* → 합계 9분 |
| 미팅 노트 (Q3 답변) | *"심사위원은 **6분 동안** 3개 종목 화면을 자유롭게 이동하며 UP/DOWN 판단"* |

**해석 가능성**

| 안 | 구조 | 총 소요 |
|---|---|---|
| **가** | 종목 3개를 **순차 제시**, 각 3분 (지난 종목으로 못 돌아감) | 9분 |
| **나** | 종목 3개를 **동시 제시**, 전체 6분 자유 이동 (문항당 3분은 권장 배분) | 6분 |
| **다** | 기본은 가(9분), **심사위원 데모만** 나(6분) 프리셋 | — |

**왜 지금 정해야 하는가**
- **F1(감수 가능 손실 한도)의 적용 단위**가 달라진다 — 세션 전체 누적인가, 종목별인가. 「위험 한도 준수」 **20점, 최대 배점 항목**의 채점 규칙이 여기 달려 있다
- 「자산 집중도」(10점) 계산 방식이 달라진다
- 스펙의 지원 평가 시간(6/12/30/60/120분)·**60배속** 진행과의 관계도 재정의 필요
- 프론트 화면 전환 구조가 달라진다 (순차 vs 자유 이동)

> ℹ️ 참고: 미팅 노트의 *"최소 평가 시간 요건 6분"*은 **대회 규정이 아니다.** 대회 요강에 평가 시간 요건은 없다.
> 스펙이 제시한 지원 시간 중 최소값이므로, 팀 내부 기준으로만 다루면 된다.

### C2 · 결과 저장 방식 — 스펙과의 긴장 두 갈래

**(a) 평가 진행 상태**
- 스펙 필수 비기능 조건: *"평가 진행 상태는 **서버에 저장**되어 재접속 후 이어갈 수 있어야 한다"*
- 미팅 결정: 로컬 스토리지 기반 **일회성 사이클**
- → **이어하기 요구가 완화된 것인지 확인 필요.** 완화됐다면 스펙 수정, 유지된다면 진행 상태는 서버·결과는 로컬로 분리

**(b) 검증 페이지의 의미**
- 결과가 로컬 스토리지에만 있으면 **제3자가 인증 코드로 조회할 수 없다**
- `INVEST PASS` 인증서 필드의 *"검증 페이지 주소"*가 사실상 **본인 확인용**이 된다
- → 기획서의 인증 서술을 **"PoC에서는 본인 확인용, 서버 기반 제3자 검증은 후속"**으로 톤다운했다 (과장 방지)

### C3 · 미완료 감점 규칙 — 스펙 배점표에 없는 신규 요소

미팅 결정: *"각 문항마다 최소 한 번 이상의 의사결정을 내려야 한다. 미완료 시 사용자에게 감점 등의 불이익"*

스펙 배점표(100점)에 **감점 항목이 없다.** 어떤 방식으로 처리할지 결정 필요.

| 안 | 방식 |
|---|---|
| 가 | 총점에서 **미결정 문항당 −N점** 차감 |
| 나 | 최소 1회 미충족 문항은 **해당 문항 관련 점수를 0 처리** |
| 다 | 미완료 시 **`INVEST PASS` 발급 자체를 불가** 처리 (감점 아닌 자격 요건) |

> **제안: 다 + 가.** 최소 1회 판단은 **평가 성립의 전제**이므로 자격 요건으로 두고, 부분 미완료는 총점 차감으로 반영한다.

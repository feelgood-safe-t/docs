## 1. MVP 구현 범위

`[구현확인]` 아래는 예상 범위. 배포본 확인 후 구현되지 않은 항목은 삭제한다

Safe-T PoC는 **판단 모드 한 가지**를 구현했다. 사용자가 성향 설문에 답하면 AI가 시나리오를 배정하고, 가속 재생되는 시장에서 상승·하락 판단과 근거를 남기면, 그 판단 과정을 평가해 결과 보고서와 교육 인증을 제공한다.

**구현한 범위**

| 영역 | 내용 |
|---|---|
| 온보딩 | 투자 성향 설문 10문항, 응답 저장 |
| 시나리오 배정 | AI가 검수된 시나리오 중 문항 세 개를 선택 |
| 시험 진행 | 독립 문항 세 개, 문항별 제한 시간, 서버 시간 기준 60배속 재생 |
| 시장 화면 | 정규화 캔들, 거래량, 시나리오 설명, 가명 뉴스·공시·커뮤니티 피드 |
| 판단 기록 | UP/DOWN, 확신도, 판단 근거 태그, 직접 입력, 정보 열람 기록 |
| 종료 제어 | 문항 조기 완료, 시험 조기 종료, 시간 만료 자동 종료 |
| 평가 | 항목별 점수 생성과 총점·통과 판정 |
| 결과 | 결과 보고서, `INVEST PASS` 발급과 확인 |

**제외한 범위** (양식 지시에 따라 본문에는 적지 않되, 심사 질의 대비용으로 팀 내부에 남긴다)

- 실제 자금 입출금, 증권사 계좌 연동, 실시간 시세
- 매수·매도 주문, 비중 설정, 손절·이익실현, 공매도·옵션
- 포지션, 보유량, 잔고, 손익, 최대 낙폭, 자산 집중도 계산
- 사용자 간 수익률 경쟁, 공인 금융 자격 발급
- 레버리지·인버스 상품 시나리오

## 3. 사용자 이용 흐름

`[구현확인]` 실제 화면 전환 순서와 대조

배포 URL에 접속한 뒤의 순서다.

```
1. 랜딩 화면에서 "바로 체험하기" 선택
2. 투자 성향 설문 10문항 응답 (약 80초)
3. AI 성향 분석 결과 확인 (성향 요약, 강점, 취약점)
4. 배정된 시나리오와 배정 근거 확인
5. 채점 기준 안내 확인 후 평가 시작
6. 문항 1 진행
   6-1. 정규화 캔들, 거래량, 시나리오 설명 확인
   6-2. 뉴스·공시·커뮤니티 피드에서 필요한 정보 열람
   6-3. UP 또는 DOWN 선택
   6-4. 확신도와 판단 근거 입력 후 제출
   6-5. 필요하면 판단 변경, 또는 문항 완료로 다음 문항 이동
7. 문항 2, 문항 3을 같은 방식으로 진행
8. 세 문항이 끝나면 시험 자동 종료 (또는 시험 종료로 조기 마감)
9. 결과 보고서 확인
10. 통과 시 INVEST PASS 확인
```

**흐름상 유의점**

- 시장은 서버 시간으로 흐른다. 사용자가 화면을 벗어나도 진행되며 다시 들어오면 그 시점부터 이어진다
- 평가 도중에는 점수나 결과를 보여주지 않는다. 모든 문항이 끝난 뒤 한 번에 공개한다
- 각 문항에서 최소 한 번은 판단해야 한다. 응답 없이 닫힌 문항은 0점이 된다

## 4. AI 및 데이터 처리 방식

### 4.1 AI가 수행하는 역할

`[구현확인]`

| 역할 | 입력 | 출력 |
|---|---|---|
| 성향 분석 | 설문 10문항 응답 | 성향 요약, 강점, 취약점, 우선 학습 항목 |
| 시나리오 선택 | 성향 분석 결과, 사전 검수된 시나리오 목록 | 문항 세 개의 선택 결과와 배정 근거 |
| 콘텐츠 각색 | 시나리오에 정의된 사실 | 가명 처리된 공시, 기사, 커뮤니티 글 |
| 판단 해석과 항목 채점 | 봉인된 판단 기록 | 항목별 점수와 근거 |
| 결과 보고서 | 항목 점수, 판단 기록 | 자연어 보고서 |

**AI가 수행하지 않는 것**

| 영역 | 처리 주체 |
|---|---|
| 캔들과 시장 데이터 생성 | 실제 과거 기록을 정규화해 재생 |
| 시장 시간 진행 | 서버 스케줄러 |
| 총점 합산, 평균, 통과 판정 | 규칙 코드 |
| 미응답 문항 0점 적용 | 규칙 코드 |

채점은 사전에 고정된 배점표에 따라 이루어진다. LLM이 항목별 점수와 근거를 생성하면 규칙 코드가 범위와 합계를 검증하고, 출력이 누락되거나 범위를 벗어나면 임의로 보정하지 않고 실패로 처리한다. 평가 결과에는 입력 해시와 채점 기준·프롬프트·모델의 버전을 함께 기록해, 같은 조건의 재요청에는 저장된 같은 결과를 반환한다.

### 4.2 사용 데이터와 입출력

`[구현확인]` 데이터 출처와 이용 조건 최종 확인 필요

| 데이터 | 성격 | 입력 | 출력 |
|---|---|---|---|
| 시장 기록 | 공개 아카이브에서 수집한 실제 1분봉 시가·고가·저가·종가·거래량 | 시나리오 제작 | 정규화·가명화된 캔들 |
| 뉴스·공시 원자료 | 원 제목, 시각, 출처, 독자적으로 작성한 사실 요약. **원문 전문은 저장하지 않는다** | 시나리오 제작 | 가명 합성 콘텐츠 |
| 시나리오 정의 | 사람이 사전 검수해 고정한 목록 | 시나리오 선택 | 배정된 문항 세 개 |
| 성향 응답 | 10문항 선택지 응답 | 성향 분석, 시나리오 선택 | 성향 요약, 배정 근거 |
| 판단 기록 | 방향, 확신도, 근거 태그와 직접 입력, 시각, 당시 정규화 가격, 정보 열람 이력 | 과정 평가 | 항목별 점수, 결과 보고서 |

가격은 시작 시점을 기준으로 정규화하며, 종목명·기업명·인물명·날짜·뉴스 원문·절대 가격은 모두 가명 처리해 사용자 화면에는 실제 정보가 노출되지 않는다.

### 4.3 개인정보 및 민감정보 처리 여부

**개인정보를 수집하지 않는다.**

- 실명, 주민등록번호, 연락처, 계좌번호, 실제 보유 종목, 실제 자산 규모를 일절 수집하지 않는다
- 회원가입과 로그인 절차가 없으며 익명 세션으로 동작한다
- 저장되는 것은 설문 선택지 응답과 서비스 안에서 생성된 가상의 판단 기록뿐이다
- 판단 기록은 실제 금융거래가 아니므로 금융거래정보에 해당하지 않는다

## 5. MVP 검증 방법

`[구현확인]` **심사에 직접 영향을 주는 항목이다. 배포본에서 실제로 확인한 절차만 적는다**

### 5.1 확인 절차

| 단계 | 확인 내용 | 예상 결과 |
|---|---|---|
| 1 | 배포 URL 접속 | 랜딩 화면. 별도 로그인 없이 바로 시작 가능 |
| 2 | 성향 설문 10문항 응답 | 한 화면에 한 문항, 진행률 표시 |
| 3 | 성향 분석 결과 확인 | 응답에 따라 달라지는 성향 요약과 취약점 |
| 4 | 시나리오 배정 확인 | 문항 세 개와 배정 근거 |
| 5 | 평가 진행 | 캔들이 가속 재생되고 시간이 지나면서 정보가 추가로 등장 |
| 6 | 정보 열람 | 뉴스·공시·커뮤니티가 구분되어 표시되고 상세 열람 가능 |
| 7 | 판단 제출 | UP/DOWN 선택 후 확신도와 근거 입력, 제출 |
| 8 | 문항 이동 | 문항 완료로 다음 문항 진행 |
| 9 | 시험 종료 | 세 문항 종료 후 결과 화면 진입 |
| 10 | 결과 확인 | 항목별 점수, 총점, 통과 여부, 자연어 보고서 |
| 11 | 인증 확인 | 통과 시 `INVEST PASS`와 인증 코드 |

### 5.2 테스트 계정과 샘플 입력값

`[미정]` 심사자용 접근 방식 확정 필요

- **계정** 별도 계정이 필요 없다. 접속 즉시 익명 세션으로 시작한다
- **샘플 응답** `[미정]` 심사자가 빠르게 진행할 수 있도록 권장 응답 조합을 제시할지 결정 필요
- **소요 시간** `[구현확인]` 설문 약 80초 + 평가 진행 시간. 심사자가 대기해야 하는 총 시간을 실측해 명시할 것
- **짧은 확인 경로** `[미정]` 전체 흐름을 다 거치지 않고 결과 화면까지 확인할 수 있는 경로를 제공할지 결정 필요

> 평가는 서버 시간으로 진행되므로 심사자가 실시간으로 대기해야 한다. **총 소요 시간을 반드시 명시**해야 하며, 짧은 확인 경로나 완료된 샘플 결과가 있으면 함께 안내한다.

### 5.3 실행 환경과 제한 사항

`[구현확인]`

- **권장 환경** `[구현확인]` 확인한 브라우저와 버전을 적는다
- **화면** 모바일 웹 우선 설계, 데스크톱 대응 `[구현확인]`
- **결과 보관** `[구현확인]` 결과가 브라우저에 저장되는 경우, **다른 브라우저나 기기로 접속하면 지난 결과가 보이지 않는다**는 점을 명시할 것
- **네트워크** 평가 도중 접속이 끊겨도 시장은 서버에서 계속 진행되며, 다시 접속하면 그 시점부터 이어진다

### 5.4 MVP 단계의 제한 사항

- 시나리오는 사전에 검수된 목록으로 한정된다. 사용자가 시장을 직접 만들 수 없다
- 레버리지·인버스 상품은 이번 시나리오에 포함되지 않는다. 관련 개념은 설문으로 확인한다
- 매수·매도, 비중 설정, 손절 등 주문 기능이 없다. UP/DOWN 방향 판단만 기록한다
- 포지션, 잔고, 손익, 최대 낙폭을 계산하지 않는다
- 실시간 시세를 사용하지 않는다. 모든 시장 데이터는 가명화·정규화된 과거 기록이다
- 발급되는 `INVEST PASS`는 자체 교육 인증이며 공인 금융 자격이 아니다

# Safe-T

## 프로젝트 정의

**Safe-T**는 실제 돈을 투자하기 전에 실제 시장을 바탕으로 만든 가명 시나리오를 경험하고, 사용자의 위험 대응과 의사결정 과정을 평가하는 AI 기반 투자 안전교육 플랫폼이다.

PoC는 사용자가 어떤 정보를 보고 어느 시점에 `UP` 또는 `DOWN` 의견을 냈으며 그 이유가 무엇인지 평가한다. 최종 수익이나 포트폴리오 성과를 평가하는 서비스가 아니다.

- 어떤 정보를 확인했는가
- 어느 시점에 방향을 판단했는가
- 판단 이유가 당시 공개 정보와 연결되는가
- 위험과 변동성 신호를 판단 근거와 확신도에 반영했는가
- 판단 근거와 확신 수준이 서로 일관되는가
- 일관된 기준으로 의사결정을 내렸는가

PoC의 `UP/DOWN`은 방향 의견이다. 주문·매수·매도·보유량·비중·현금·노출·포지션을 만들지 않으며, 의견을 암묵적인 “표준 가상 포지션”으로 변환하지 않는다.

평가를 통과한 사용자에게는 플랫폼 자체 교육 인증인 `INVEST PASS`를 발급한다. 이는 공인 금융 자격이나 실제 투자 적격성을 뜻하지 않는다.

## 제품 구조와 PoC 범위

| 모드 | 내용 | 상태 |
|---|---|---|
| 캐주얼 판단 시험 | 가명 시장 문항 세 개를 문항당 최대 3분씩 순차적으로 풀고 UP/DOWN과 이유를 기록 | **PoC 범위** |
| 포지션·거래 고도화 | 가상 자금, 주문, 체결, 보유량, 비중, 현금과 포트폴리오 위험 지표를 다루는 실전형 모드 | **WIP, PoC 제외** |

캐주얼 판단 시험은 실전형 모드의 축소 포트폴리오가 아니라 독립적인 의견 증거 기반 교육 평가다. 서버는 문항 진행 상태와 행동 이력을 저장하지만 문항 사이에 포지션이나 자산 상태를 이월하지 않는다.

PoC는 다음 기능을 검증한다.

- 성향 설문과 외부 AI 분석
- 검수된 시나리오 문항 배정
- 서버 시계 기반 시장 상황 재생
- 시점별 방향·필수 이유·정보 열람 기록
- 세 문항의 불변 평가 입력 생성
- LLM 기반 항목별 분석과 규칙 기반 합산
- 교육 보고서와 PASS 발급

포지션·거래 고도화 모드는 화면에 `준비 중`으로 표시하며 현재 API, Snapshot, 점수와 PASS에 어떠한 영향도 주지 않는다.

## 핵심 사용자 흐름

```text
성향 설문
→ 외부 AI 성향 분석
→ 검수된 시장 문항 3개 선택
→ 문항 1: 최대 3분 관찰·판단·완료
→ 문항 2: 최대 3분 관찰·판단·완료
→ 문항 3: 최대 3분 관찰·판단·완료
→ 불변 Evaluation Snapshot 생성
→ LLM 항목별 분석 + 규칙 기반 점수·PASS
→ 결과 보고서와 INVEST PASS
```

사용자는 앞 문항이 닫힌 뒤에만 다음 문항을 볼 수 있다. 전체 시험의 최대 유효 응시 시간은 9분이며 문항 조기 완료에 따라 짧아질 수 있다.

## PoC 기능 범위

### 사용자 성향 분석

사용자는 평가 시작 전 다음 항목에 응답한다.

- 투자 경험
- 위험 선호도
- 레버리지 상품 특성 이해도
- 불리한 가격 움직임에 대한 대응 성향
- 정보 출처 검증 습관
- 관심 자산 및 산업
- 평가 중 감수 가능한 불확실성 수준
- 주로 고려하는 투자 기간
- 가격 방향 판단 시 우선 확인하는 근거
- 평가에서 확인하고 싶은 학습 목표

외부 AI 서비스는 응답을 기반으로 다음 결과를 생성한다.

- 사용자 성향 요약
- 주요 강점과 취약점
- 우선 학습 항목
- 사전에 검수된 후보 안에서의 문항 추천

백엔드 중앙 엔진은 설문 질문과 원본 답만 저장한다. 성향 해석, 추천 결과와 LLM 실행은 엔진 범위 밖이다.

### 시험과 문항 구조

한 번의 시험은 순서가 고정된 `AssessmentItem` 정확히 세 개로 구성한다.

- 각 item은 하나의 독립적인 시장 판단 문항이다.
- 각 item에는 판단 대상인 단일 가명 자산이 있다.
- 한 번에 현재 item 하나만 공개한다.
- 이전 item의 의견은 다음 item의 현재 의견이나 포지션으로 이어지지 않는다.
- 각 item에는 제한 시간 안에 `UP` 또는 `DOWN` 의견을 최소 한 번 남겨야 한다.
- 시장이 진행되는 동안 UP/DOWN을 아무 때나 몇 번이고 누를 수 있다.
- 이미 기록된 판단을 수정·삭제·덮어쓰는 기능은 없다. 매 입력은 독립된 판단 이벤트로
  시간순 누적하며 같은 방향의 재입력과 다른 방향의 후속 입력을 모두 허용한다.

### 원천 자료와 시나리오 제작

각 item은 특정 실제 자산의 과거 시점 전후 자료를 기반으로 한다. 제작 입력은 다음 세 요소다.

1. 해당 구간의 실제 OHLC 캔들과 거래량
2. 어떤 사건·시장 국면인지 설명하는 짧은 사실 명세
3. 그 시점에 실제로 공개된 뉴스와 공시

원천 자료를 참가자에게 그대로 제공하면 자산명, 가격대, 날짜와 기사 검색을 통해 원본 자산·시점과 이후 실제 흐름을 미리 알아낼 수 있으므로 외부 시나리오 제작 파이프라인에서 다음 처리를 수행한다.

```text
실제 캔들 + 사건 명세 + 실제 뉴스
→ 자산·기업·인물·날짜 가명화
→ 가격의 결정론적 정규화
→ 외부 LLM으로 뉴스 제목·본문을 교육용 가명 콘텐츠로 재작성
→ 사람의 사실·미래정보·재식별 위험 검수
→ 버전이 고정된 게시용 Runtime Scenario
```

이 LLM 활용은 시나리오 제작 단계의 외부 기능이며 중앙 백엔드 엔진에는 포함하지 않는다. 엔진은 검수 완료된 `APPROVED` package만 import하고, 자체 구조 검증을 통과해 `PUBLISHED`가 된 `ScenarioVersion`만 세션에 배정·재생한다.

### 가격과 캔들 가명화

가격은 source 시작 가격 `P0`와 시나리오에 고정된 비식별 시작값 `B`로 정규화한다.

```text
정규화 가격(t) = 실제 가격(t) / P0 × B
```

- 모든 OHLC에 같은 배율과 버전이 고정된 반올림 규칙을 적용한다.
- 정규화 후에도 원천 가격계열의 상대 변화율과 OHLC 대소 관계를 보존한다.
- 실제 절대 가격과 실제 날짜는 Runtime Scenario에 넣지 않는다.
- LLM은 캔들·가격·거래량·시장 시각을 생성하거나 임의 수정하지 않는다.
- 동일한 제작 입력과 정책 버전은 동일한 정규화 결과를 만들어야 한다.

문항에는 시작 시 볼 수 있는 pre-roll 캔들과 3분 동안 표시할 캔들을 모두 준비한다. 현재 PoC
참가자 API는 현재 item의 전체 데이터를 한 번에 전달하고 프론트가 offset에 따라 표시한다.
Evaluation Snapshot은 전체 ScenarioVersion을 복사하지 않고 응답 전후 window와 뉴스
공개·열람 상태만 평가 근거로 봉인한다.

### 짧은 시나리오 명세

현재 문항을 이해하는 데 필요한 짧은 설명을 제공한다.

- 실명·실제 날짜·실제 가격과 이후 실제 가격 흐름을 포함하지 않는다.
- 사건 유형, 관찰할 위험과 필요한 과업만 설명한다.
- 참가자 화면에서 빠르게 읽을 수 있는 제목과 단락 하나 수준으로 제한한다.
- ScenarioVersion 게시 후에는 수정하지 않는다.

### 실제 뉴스 기반 가명 합성 콘텐츠

가명 합성 뉴스는 실제 당시 뉴스·공시의 확인된 사실을 근거로 외부 LLM이 제목과 본문을 재작성한 교육용 콘텐츠다. 실제 사회에 배포할 허위 뉴스가 아니며 Safe-T 시험 안에서만 사용한다.

제작 원칙은 다음과 같다.

- 실존 기업·인물·종목·지역·날짜를 제거하거나 일관된 가명·상대 시각으로 바꾼다.
- 실제 제목·본문을 그대로 복사하지 않는다.
- source에 없는 사실이나 미래 시점 사실을 추가하지 않는다.
- 핵심 사실, 사건 순서, 출처 유형과 공개 상대 시각을 보존한다.
- 실제 URL, 원문 hash와 alias map은 격리된 외부 감사 저장소에만 보존한다.
- prompt·model·변환 정책과 결과 hash를 제작 artifact에 버전으로 남긴다.
- 사람이 승인한 콘텐츠만 게시한다.
- 모든 콘텐츠에 `AI 가명화·재작성 시뮬레이션 콘텐츠` 고지를 표시한다.
- 실제 투자 추천 문구를 만들지 않는다.

원문 뉴스, 실제 식별자와 대응표는 중앙 엔진의 DB, API, 로그와 Evaluation Snapshot에 포함하지 않는다.

### 문항 시간과 시장 진행

각 item의 실제 제한 시간은 180초다. 시장은 서비스 시간보다 60배 빠르게 진행한다.

```text
서비스 1분 = 시장 시간 60분
문항 3분 = 시장 시간 180분 = 10,800,000ms
```

- timer는 item을 활성화한 권위 있는 서버 시각에 시작한다.
- 신규 행동은 `[startedAt, deadlineAt)` 구간에서만 받는다.
- 사용자가 화면을 나가도 timer와 시장은 계속 진행한다.
- 재접속 시 서버 현재 시각에 맞는 현재 item과 공개 범위를 복원한다.
- deadline에 도달하면 현재 item을 timeout으로 닫고 다음 item을 순차적으로 시작한다.
- 미래 item은 잠금 상태로 유지한다. 현재 PoC는 현재 item의 캔들·뉴스 전체를 한 번에
  전달하고 프론트가 공개 offset에 맞춰 표시한다.

장시간 이탈해 여러 deadline이 지나면 남은 item도 순서대로 timeout될 수 있다.

### UP/DOWN과 판단 이유

사용자는 현재 item의 단일 가명 자산에 대해 UP 또는 DOWN 의견을 제한 시간 동안 수시로
제출할 수 있다.

- `UP`: 현재 공개된 정보를 보고 앞으로 상승할 것 같다고 판단
- `DOWN`: 현재 공개된 정보를 보고 앞으로 하락할 것 같다고 판단

이는 거래 액션이나 사후 가격 예측 채점이 아니라, **각 입력 시점에 사용자가 느낀 향후
방향**을 기록하는 판단 이벤트다. 최초 판단뿐 아니라 같은 방향의 재확인과 다른 방향의 후속
판단도 모두 별개 증거로 보존한다. 각 판단 이벤트에는 다음 값이 필요하다.

- 필수 판단 근거 태그 한 개 이상: 가격, 거래량, 시나리오 설명, 뉴스, 직감, 기타
- 필수 확신도: 낮음, 보통, 높음
- 선택적 1~500자 직접 입력 이유

직접 입력을 생략할 수 있지만 판단 근거 태그와 확신도는 생략할 수 없다. 직접 입력 값이 있으면 공백뿐인 문자열은 저장하지 않는다.

각 판단 이벤트는 다음 사실과 함께 기록한다.

```text
사용자와 시험
assessment item ID와 순서
scenario version과 가명 자산
UP/DOWN 방향
필수 확신도
필수 판단 근거 태그와 선택적 직접 입력 원문
서버 수신 시각과 item-local 시장 시점
당시 응답 기준이 된 정규화 가격
세션 전역 event sequence
```

뉴스 목록이 화면에 나타난 사실과 사용자가 상세 본문을 실제로 연 사실을 구분해 기록한다.
후단 LLM이 판단 빈도, 시점, 방향 전환, 확신도·근거 변화와 정보 열람의 선후관계를 평가할
수 있도록 모든 판단과 열람 이벤트에 세션 전역 sequence를 부여한다.

### 문항 완료와 전체 시험 종료

현재 item에 응답을 제출하면 `문항 완료/다음`을 선택해 180초 전에 다음 item으로 이동할 수 있다.

- 문항 조기 완료 자체에는 고정 감점이 없다.
- 응답이 없는 item은 문항 완료로 처리할 수 없다.
- timeout 시 응답이 있으면 답변한 item, 없으면 미완료 item이다.
- 세 번째 item이 닫히면 전체 시험이 자동 종료된다.

별도의 `시험 종료` 버튼으로 `ACTIVE` 시험을 언제든 조기 종료할 수 있다.

- 이미 답변한 item은 정상 평가 대상이다.
- 현재 item에 의견이 없으면 미완료로 닫는다.
- 아직 시작하지 않은 item도 미완료로 닫는다.
- 조기 종료 행위 자체에 별도 고정 감점은 없다.
- 미완료 item에는 후단 규칙 코드가 item 점수 0을 적용한다.
- 답변한 item이라도 관찰 가능한 행동 이력이 적으면 공개된 `rubricVersion`의 해당 과정 평가 항목에서 활용할 증거가 적을 수 있다. 조기 종료 행위 자체에 대한 별도 숨은 감점은 없으며 이는 중앙 엔진의 판단이 아니다.

item과 시험이 끝난 뒤에는 상태·종료 사유·시각과 원본 행동을 수정할 수 없다.

## 포지션 없는 판단 증거

캐주얼 판단 시험에는 실제 주문과 자금 배분이 없으며 내부적으로도 가상 포지션을 만들지 않는다.

- `UP`은 매수, long 또는 가상 노출이 아니다.
- `DOWN`은 매도, short, 현금 전환 또는 노출 제거가 아니다.
- 이미 기록된 UP/DOWN은 수정하거나 지우지 않는다. 이후 UP/DOWN 입력은 새 이벤트다.

따라서 PoC 엔진과 평가기는 다음 포트폴리오 지표를 계산하지 않는다.

- 가상 수익률과 PnL
- 최대 낙폭(MDD)
- 유효 레버리지와 위험 노출 시간
- 자산 집중도와 현금 비중

후단 LLM은 초기 성향 설문 응답, 모든 UP/DOWN 판단 이벤트, 필수 태그·확신도, 선택적 직접
입력, 각 판단 직전·직후 시장 흐름, 각 판단 시점에 이용 가능했던 뉴스와 실제 열람 여부를
과정 평가 증거로 사용한다. 판단 후 가격 흐름은 맥락일 뿐 정답이 아니며 방향 적중률을
계산하지 않는다.

## Evaluation Snapshot과 시스템 분리

중앙 엔진은 시험 종료 후 다음 자료를 하나의 불변 Snapshot으로 봉인한다.

- 설문 버전·질문·원본 답변
- 순서가 고정된 AssessmentItem 세 개와 ScenarioVersion checksum
- item별 시작·deadline·종료 시각과 종료 사유
- item별 판단 이벤트 수와 `ANSWERED/UNANSWERED`
- 가명 자산과 짧은 시나리오 명세
- 시간순으로 누적된 모든 판단 이벤트와 각 이벤트의 필수 판단 태그·필수 확신도·선택적
  직접 입력
- 각 판단 기준 완성 캔들을 중심으로 직전 10개와 직후 10개만 담은 1분봉 window
- 각 판단 직전과 직후 window의 가격 변화·범위·평균 거래량 요약
- 각 판단 시점에 이용 가능했던 뉴스와 그전 실제 열람 여부·최초 열람 시점
- 각 판단 직후 window에 새로 도착한, 해당 판단 당시에는 알 수 없었던 뉴스
- item 전체의 상세 뉴스 열람 이벤트 타임라인
- 엔진·schema·canonicalization 버전과 payload hash

Snapshot은 프론트 재생용 240개 캔들과 뉴스 전체를 복사하지 않는다. LLM이 모든 판단 시점을
바로 평가할 수 있도록 판단 이벤트마다 제한된 전후 캔들 window와 뉴스 공개·열람 상태를
함께 구조화한다. 판단 후 window는 행동의 효용을 이해하는 맥락이며 정답 라벨이 아니다.

Snapshot에는 LLM prompt·model, 점수, PASS, 보고서, 포지션 또는 실제 원천 자료를 넣지 않는다. 후단 Evaluation Service는 `snapshotHash`와 함께 rubric·prompt·model 버전과 구조화 결과를 별도 저장한다.

## 과정 평가

### 문항 완료 gate

후단 규칙 코드는 LLM 호출 전에 각 item의 `answerStatus`를 확인한다.

- `UNANSWERED`: 해당 item의 최종 점수는 정확히 `0`
- `ANSWERED`: 고정 rubric에 따라 LLM이 항목별 점수와 근거를 구조화해 반환
- `USER_COMPLETED`: 이 종료 사유만으로 감점하지 않음

한 item이라도 미완료면 0점 불이익을 받는다. 완료 여부와 0점 적용은 LLM 추론이 아니라 결정론적 규칙이다.

### 항목별 평가

답변한 각 item은 100점 만점으로 다음 항목을 평가한다. 항목별 점수는 LLM이 Snapshot에 기록된 **당시 공개 정보와 판단 과정만** 사용해 생성하고 규칙 코드가 범위와 합계를 검증한다.

평가에서 말하는 판단의 효용은 가격을 맞혔는지가 아니다. 각 판단 당시 이용 가능했던 제한된
정보에서 근거를 선택하고 확신도를 표현하며, 시간에 따른 판단·근거·확신도의 변화가 새 정보와
시장 맥락에 비추어 숙고된 과정인지 평가한다. 단순히 여러 번 눌렀거나 방향을 바꿨다는 사실
자체를 정답·오답으로 취급하지 않는다. 선택적인 직접 입력을 제출하지 않았다는 사실만으로
감점하지 않는다.

| 평가 항목 | 배점 | 판단 증거 |
|---|---:|---|
| 위험 신호 인식과 대응 | 20 | 변동성·거래량·뉴스의 위험 신호를 응답 근거에 반영했는지 |
| 불확실성과 변동성 인식 | 15 | 당시 정보의 불확실성과 가격 변동성을 판단 태그·확신도에 반영했는지 |
| 정보 활용과 출처 구분 | 15 | 시나리오 설명과 가명 뉴스의 역할을 구분하고 필요한 상세 정보를 열람했는지 |
| 시장 흐름 해석 | 15 | 당시 공개된 캔들·거래량·사건을 UP/DOWN 판단과 연결했는지 |
| 초기 성향과 응답의 정합성 | 15 | 설문에서 밝힌 정보 활용·위험 인식 성향과 실제 응답이 어떻게 이어지는지 |
| 판단·확신도·근거의 일관성 | 10 | 각 시점의 UP/DOWN·확신도·근거가 서로 부합하고, 후속 판단 변화가 새 정보나 시장 흐름과 일관되게 연결되는지 |
| 판단 근거의 유용성 | 10 | 선택한 근거가 당시 의사결정에 실질적으로 유용하고 서로 모순되지 않는지 |
| **합계** | **100** |  |

이번 PoC의 Runtime Scenario에는 레버리지·인버스 상품을 사용하지 않는다. 향후 해당 상품을 시나리오에 넣으려면 상품 유형과 배수를 Scenario schema에 먼저 명시해야 한다.

### 총점과 통과 조건

- 문항별 점수 범위: `0..100`
- 최종 점수: `(item1Score + item2Score + item3Score) / 3`
- 반올림 전 최종 점수 `70` 이상이면 PASS
- 각 항목 점수는 `0..배점` 범위의 소수점 한 자리이며 문항 점수는 항목 합계다.
- 범위 검증, 항목 합계, 미완료 0점 적용, 평균과 PASS 판정은 규칙 코드가 수행한다.
- LLM 출력이 누락되거나 범위를 벗어나면 값을 임의 clamp하지 않고 실패로 거부한 뒤 versioned 재시도 정책을 적용한다.
- `(snapshotHash, rubricVersion, promptVersion, modelVersion)`이 같은 평가 재요청은 저장된 동일 결과를 반환한다.

미완료 item 하나가 있으면 이론상 최고 최종 점수가 `66.666...`이므로 PASS할 수 없다. 이는 세 문항을 모두 해결하도록 하는 미완료 불이익이다.

방향 적중 여부와 사후 가격 수익률은 계산·표시·채점하지 않는다.

## AI와 규칙 코드의 역할

| 주체 | 처리 내용 |
|---|---|
| Selection AI | 설문 응답을 강점·취약점·학습 항목으로 정리하고 검수 후보 중 세 문항 추천 |
| 외부 Scenario Builder LLM | 실제 뉴스의 확인된 사실을 교육용 가명 뉴스로 재작성 |
| Backend Engine | 서버 timer, 미래 item 잠금, 현재 item 전달, 행동 원본, 완료 사실과 Snapshot |
| Evaluation LLM | 답변 item의 항목별 점수·근거와 개선 의견을 구조화해 생성 |
| Result Rules | 미완료 item 0점, 점수 범위·합계 검증, 평균과 PASS 결정 |
| Report/Pass Service | 교육 보고서와 INVEST PASS 발급·조회·검증 |

AI가 담당하지 않는 영역은 다음과 같다.

- 캔들·가격·거래량과 시장 시각 생성
- 가격 정규화 계산
- item timer와 상태 전이
- item별 최소 1회 판단 여부 검증과 미완료 판정
- 미완료 0점, 총점 평균과 PASS 판정
- Snapshot canonicalization과 hash

## 결과 보고서와 INVEST PASS

### 결과 보고서

평가 종료 후 다음 내용을 제공한다.

- 최종 점수와 PASS 여부
- 세 item의 완료 상태·종료 사유·문항별 점수
- 항목별 점수와 근거
- 제출한 UP/DOWN과 판단 이유
- 응답 시점의 시장·뉴스 정보와 열람 이력
- 확인한 정보 출처
- 가장 적절했던 판단과 위험했던 판단
- 반복된 행동 패턴과 개선할 투자 습관
- 추천 후속 학습

가상 포지션 수익률, PnL, MDD, 유효 레버리지와 자산 집중도는 보고서에 포함하지 않는다.

### INVEST PASS

PASS 시 다음과 같은 인증을 발급한다.

```text
INVEST PASS L1
9-Minute / 3-Question Market Judgment Assessment
```

인증에는 인증 코드, 평가 형식 `3×3분`, 시나리오 유형, 최종 점수, 발급일, 검증 페이지 주소와 민간 교육 인증 안내를 포함한다.

> 본 인증은 Safe-T가 발급하는 자체 교육 인증이며, 공인 금융 자격 또는 실제 투자 적격성을 의미하지 않습니다.

## PoC 제외 및 포지션·거래 WIP

다음 기능은 이번 PoC에서 구현하지 않는다.

- 실제 돈 입출금과 증권사 계좌 연동
- 실시간 주가와 실제 종목 추천
- 가상 자금, 매수·매도 주문과 체결
- 보유량, 평균단가, 현금 잔고와 사용자 직접 비중
- 손절매·이익실현·공매도·옵션 주문
- long·short·inverse·leverage exposure 계산
- 포트폴리오 PnL·수익률·MDD·유효 레버리지·집중도
- 사용자 간 수익률 경쟁
- 공식 금융 자격 발급
- AI가 자유롭게 생성하는 시장 가격과 무한 시나리오

이 기능들은 별도 `포지션·거래 고도화` WIP다. 별도 승인된 명세·schema·migration·API·평가 rubric이 준비되기 전까지 현재 PoC에 필드만 미리 추가하거나 `UP/DOWN`에서 암묵적으로 추론해서는 안 된다.

## 필수 비기능 조건

- 시나리오·설문·Snapshot과 평가 rubric은 immutable version으로 관리한다.
- item timer와 행동 수락은 권위 있는 서버 시각을 사용한다.
- item 종료와 다음 item 시작은 원자적으로 처리한다.
- terminal item과 Snapshot은 수정하거나 덮어쓰지 않는다.
- 동일한 저장 사실은 동일한 canonical Snapshot과 hash를 만들어야 한다.
- 참가자에게 미래 item, 미래 캔들, 실제 종목·기업·인물·날짜·가격과 원문 뉴스를 노출하지 않는다.
- 외부 LLM 가명화 결과는 사람이 승인하기 전 게시하지 않는다.
- 원천 자료·alias map 저장소와 Runtime Backend Engine의 계정·네트워크 권한을 분리한다.
- 평가 결과에는 `snapshotHash`, `rubricVersion`, `promptVersion`, `modelVersion`과 구조화 출력 hash를 기록한다.
- 모든 화면과 결과에 투자 추천이 아닌 교육용 시뮬레이션임을 표시한다.
- PoC에서는 실명, 실제 계좌와 실제 자산 규모를 수집하지 않는다.
